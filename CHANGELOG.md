# Changelog

## 0.2.3

- Signing out or shutting down while a PecoFence menu is open shows the Windows desktop icons again and keeps the last changes. With a menu open, Windows closes the menu and ends PecoFence at once, before it is told about the sign-out, so the icons stayed hidden until PecoFence started again (in 0.2.2 and earlier), and a fence moved just before the menu opened was back where it had been. PecoFence now shows the icons when Windows closes the menu for a sign-out, and saves its changes before any menu opens.
- Folders shown on the desktop (「在桌面显示文件夹」) notice when their folder on a local disk is renamed or moved away. The fence kept showing the old files, because its watch went along with the folder to its new name or place; within a minute it now says 「找不到此文件夹。」, shows the files of a new folder made at the same path, and shows the folder again when it is renamed back.
- In Fluent, a right click cancels moving a fence by its title also while the pointer rests, as Esc does and as in Liquid Glass. Windows' own move loop only reports the pointer while it moves, so a right click on a resting pointer went unseen and the fence stayed where the left button came up.
- Portable copies start with Windows with their own configuration. The startup entry started the copy without `--portable`, so at sign-in it opened the %APPDATA% configuration and showed the first-start fences; it now carries `--portable`, and an entry an earlier version wrote gets it the next time the copy is started with `--portable`. 「随 Windows 启动」 shows whether the entry starts this copy: a new portable copy said on although nothing started it with Windows.
- In the Store edition, 「随 Windows 启动」 shows the switch Windows keeps for PecoFence (Windows Settings › Apps › Startup). A click opens that page, as before, but no longer flips the switch in PecoFence by itself, and a change made on that page shows when you come back to PecoFence's Settings.
- On Windows 10 without its September 2023 update, 「关于」 and `pecofence-cli status` show PecoFence's memory again instead of 0.0 MB. 「关于」 no longer says "for Windows 11" on Windows 10.
- Folders get their icon asked again after a start at sign-in, like the other icons (feedback #11). Since 0.2.2 folders show a preview of their contents and were left out of the re-checks half a minute, two minutes and ten minutes after the start, so a folder that got the wrong icon at sign-in kept it.
- A new `.tmp` file on the desktop shows in a fence once it has lasted a minute. It waited for the next minute tick, and with the Windows desktop icons shown for the next change on the desktop.
- Shortcuts PecoFence makes, for example with Alt held while dragging into a folder fence, are named in the Windows display language, as Explorer names them (`Report - Shortcut.lnk` on English Windows), whatever language PecoFence shows.
- The roll-up chevron shows when the pointer goes straight from a fence's border onto a tab, from a tab onto the gap between two tabs, and after the first click on a cut-off tab; it showed only after the pointer moved again, and on Windows 10 the first click after a start often lost it (also in 0.2.2).
- Windows 11's snap layouts popup (after Win+Up) and the task switcher no longer count as an app coming to the front. Taken for one, the popup ended a Peek, so the search you typed went to the window below, turned off the desktop's double-click that hides the fences, or ended Win+D's floating fences (also in 0.2.2).
- Screen readers read the rule buttons in Settings › 整理规则 with the colon of the UI language (`Move up: Programs and shortcuts`).
- The Store edition starts its wait for the rating notice at the first start; the first start could not record itself and the wait began one start later.
- A folder fence whose folder is gone no longer writes a warning to the log at every change on the desktop.

## 0.2.2

- Tabs that do not fit the title row keep their whole names (#82; thanks to @xan2622, who also proposed wrapping them in #83). Until now every tab shrank until its name was cut to 「Pro…」 or just 「…」. The tabs now keep their width and the strip scrolls instead: switching to a tab (a click, the wheel on the title row, Ctrl+Tab, a Peek search) slides it into view with a little of the next tab showing, and an end with more tabs behind it fades out. While the roll-up chevron is hidden the strip also uses its place. Dragging a tab, or another fence to merge it, to an end of the strip scrolls it that way. A rolled fence with many tabs shows its item count again whenever two tabs fit beside it. The left tab column is unchanged.
- A fence dropped on another fence's tabs in Fluent lands in the gap that opened under the pointer. It used to land one place off, because the gap was closed before the drop was placed; Liquid Glass had the same trouble with a strip that scrolls.
- Icon names can stay white in Liquid Glass (#64): 「图标名称颜色」 (Settings › 常规 › 外观, or `pecofence-cli settings set labelColor white`) offers 「自动」, 「白色」 and 「黑色」. 「自动」 is the default and works as before: Liquid Glass picks dark or light names from the wallpaper behind each fence, so a fence over a bright sky could show dark names with a light halo while the fence below showed white ones, and Fluent follows the colour mode. 「白色」 and 「黑色」 keep the item names in that colour in every fence and view (icons, list, details), in both Fluent and Liquid Glass, whatever the wallpaper; white names get a dark halo and dark names a light one, as before. Fence titles keep their own 「标题颜色」.
- A rule can take every file the other rules left (#71, also asked in #69 and #70). The new condition 「普通文件」 (Settings › 整理规则 › 新建规则 › 条件类型, or `pecofence-cli rule add --plain-files`) matches any file that is not a folder, a program, a shortcut, This PC or the Recycle Bin. Rules go by first match, so a 「普通文件」 rule at the end of the list collects whatever the archive, document and image rules before it did not take, `.sql`, `.html` and unknown extensions included, and programs and shortcuts never land in it. Settings adds a new 「普通文件」 rule at the end of the list, where such a rule belongs; every other new rule still goes first. A configuration with such a rule still opens in 0.2.1, which reads the rule as 「仅文件」.
- Icons that no rule matches can stay in their fence when the rules are applied (#71, #69). The new setting 「没有命中规则的项目」 (Settings › 整理规则) has 「回到“桌面”栅栏」, the default and the behaviour until now, and 「留在当前栅栏」. With 「留在当前栅栏」, 「立即应用」, the tray's 「立即应用整理规则」 and `pecofence-cli rule apply` (and its `--dry-run`) leave such an icon where it is, so turning off the rule that filed your shortcuts no longer sends them back to 「桌面」. Icons new on the desktop that no rule matches still go to 「桌面」. In `rule list` and `rule import` it is `"unmatched": "stay"` (default `"defaultTarget"`).
- `.tsv` files count as documents, like `.csv`, so the 「文件与文档」 rule and other document rules file them (feedback #28).
- 「在此新建栅栏」 after a box on the empty desktop can be turned off (feedback #3, and requests on appinn): switch off 「在桌面空白处拖出矩形时提供“在此新建栅栏”」 in Settings › 常规 › 桌面与启动, or run `pecofence-cli settings set offerNewFence false`. A box dragged on the empty desktop then still selects the fences it touches, and a box that touches none offers nothing; new fences still come from 「新建栅栏」 in the tray menu and the fence menu. It stays on by default.
- The 「桌面」 fence can stay hidden while the Windows desktop icons show (feedback #4, #21, and requests on linux.do and appinn). With 「隐藏 Windows 桌面图标」 off, switch on 「显示 Windows 桌面图标时隐藏“桌面”栅栏」 just under it (Settings › 常规 › 桌面与启动, or `pecofence-cli settings set hideInboxWhenIconsShown true`). The fences then show only what the rules or you put in them, and everything else is only on the Windows desktop, so it no longer shows twice. An icon dragged out of a fence onto the desktop goes back to 「桌面」 as before, so it simply leaves the fence. Turning 「隐藏 Windows 桌面图标」 on again brings the 「桌面」 fence back. As with 「为空时自动隐藏」, a 「桌面」 fence that is a tab of another fence, or holds tabs, stays shown. Off by default.
- Folders show what is inside them, as on the Windows 11 desktop (#120): a folder of pictures shows one of them in the folder, a folder of documents shows a page, and an empty folder keeps the plain folder icon. The 「列表」 and 「详细信息」 views keep plain folder icons, as Explorer's do. With 「始终显示图标，从不显示缩略图」 on in File Explorer Options, folders show the plain icon too, as pictures and videos already did. On a test desktop with 36 folders of pictures the fences had every icon ready as quickly as before once Windows had the previews in its thumbnail cache; the first start after that cache was emptied took about half a second longer.
- Shortcuts show Windows' shortcut arrow at the bottom left of their icon, as on the desktop (feedback #3, #37), so a shortcut and the file or folder it opens can be told apart: .lnk and .url files and the other shortcut kinds such as .website and .appref-ms, in the icon, list and details views, at every icon size and display scaling, with the arrow as large as Explorer draws it. PecoFence uses the arrow Windows itself uses, so an arrow you replaced or removed in Windows (the `Shell Icons` value 29) looks the same in the fences. The arrows are on after the update; to turn them off, switch off 「显示快捷方式箭头」 in Settings › 常规 › 外观, or run `pecofence-cli settings set icons.shortcutArrows false`.
- Menus follow the colour mode (feedback #3). When 「颜色模式」 (Settings › 常规) comes out dark, the fence menu, an icon's menu with Windows' own entries in it, their submenus and the tray menu are dark too, and light when it comes out light. A change of the mode, also one PecoFence follows from Windows, shows from the next menu on. Windows 10 before version 1903 keeps light menus.
- Space opens QuickLook's preview of the selected icon in a fence, as it does on the desktop and in Explorer, while QuickLook (github.com/QL-Win/QuickLook) runs (feedback #2, #3). Space again closes it, the arrow keys show the icon they move to in the open preview, and Esc closes it. A space typed right after letters, while picking an icon by typing its name, still belongs to the name, and Ctrl+Space still adds the focused icon to the selection or takes it out. Without QuickLook, Space does nothing, as before.
- The title bar can show the fence's name alone (feedback #29). With 「隐藏标题栏右侧的项目数和折叠箭头」 on (Settings › 常规 › 行为, or `pecofence-cli settings set rollUp.hideCountAndChevron true`), a rolled-up fence no longer shows how many items it holds, and no fence shows the roll-up chevron, also at the bottom of a left tab column. Double-click the title, or use 「收起」 and 「展开」 in the fence menu, to roll a fence up and down; where the chevron was, the title drags, double-clicks and opens the menu like the rest of it. The setting is off by default, because a rolled-up fence without them looks like a fence that only has a title.
- A folder portal merged into a tab strip shows the folder icon before its name, as it does before its title on its own (#86, by @xan2622). Its tab looked like any other until now, although files dropped on it move into a real folder. In the left tab column, the names of every tab move over to stay aligned once one of them is a folder. Turning off 「标题栏显示文件夹图标」 in the fence options hides it in the tab too.
- The selected tab's background stays on its tab when Peek switches a fence to the tab with matches. The background glides to the new tab, and when the match counts widened the tabs during that glide it stopped where the tab had been before, half over the next tab, until something redrew the fence.
- PecoFence keeps up with many desktop files at once (#122). In a Windows 11 test machine, 500 files created on the desktop together all showed in 0.55 s instead of 1 s, at a fifth of the CPU time; a start with 1,000 files on the desktop no longer freezes the fences' fade-in for most of a second; and the first fence shows sooner when Explorer is busy at sign-in (0.25 s instead of 0.66 s). A fence with many items asks for the icons of the rows in view first, and changes inside a portal's folder no longer make PecoFence read the whole desktop again.
- More configurations load as they are (#122). A `config.json` saved as UTF-8 with a BOM, as some editors do, was set aside as broken and PecoFence started with the first-start fences; it now loads, imports and passes `pecofence-cli config check`. One fence size out of range is brought into range instead of costing the whole file, a fence or item listed twice shows once, and a file another program holds open for a moment at startup is read once it is free. A configuration whose tabs name each other as their host no longer hangs PecoFence at full CPU before any fence shows. When a save cannot replace `config.json`, the previous file is put back, and a configuration PecoFence cannot save says so once in the tray, with its folder.
- The first-start fences stay on a small screen at a high scale, such as 1024×768 at 150 % or 1366×768 at 125 % (#122).
- Folders shown on the desktop (「在桌面显示文件夹」) follow their folder again after it was deleted, or on a drive that went away, and came back (#122); the fence used to stop updating until PecoFence restarted. A folder that is gone now says so instead of 「此文件夹为空。」. A folder on a network share or a mapped network drive shows its files (feedback #41, #43), also when the fence was made with 0.2.1, which saved the path wrongly, and a share that cannot be reached no longer stalls the fences once a minute.
- Renaming is safer (#122). Emptying the name box keeps the old name, where `notes.txt` with its extension hidden became `.txt`; a name Windows cannot use keeps the box open; a rename or a new item never replaces a file another program has just created; items whose path is 260 characters or longer can be renamed again; and renaming an item to the name of a file deleted a moment ago keeps it in its fence.
- Dragging into a folder shown on the desktop works like Explorer (#122): Ctrl copies and Alt makes a shortcut, where the files were always moved, and a plain drag onto a folder on another drive copies. Cut and paste keeps the files on the clipboard until the move went through. A right-button drag from an item no longer opens the menu of the item it was released over, and a link dragged from a browser onto a folder item lands in that folder.
- Esc cancels moving a fence, or a group of selected fences, by its title also in Fluent and without a click in the fence first, and so does the right button (in Fluent while the pointer moves) (#122). Cancelling a tab tear-off or an item drag with the right button no longer leaves the fence menu open. The scroll bar can be grabbed across its whole width; a fence or a torn-off tab dropped partly off the screen is pulled back onto it, while a fence across two monitors stays where it is; and the fences are no longer always on top after Win+D twice with no app window open.
- After a crash with the Windows desktop icons hidden, the watchdog shows them again also when Explorer restarts or hangs (#122).
- Choosing the Peek shortcut again after PecoFence fell back to another one switches back to it once it is free (#112, #122), and a configuration from 0.2.0 that chose Win+Space no longer shows the "shortcut in use" notice at every start. The shortcut box says a combination may be taken by another program when its keys stop arriving.
- Leftover `.bak` files on the desktop show in a fence, and `.tmp` files do once they are a minute old (#122), so they no longer sit unseen behind the fences; Office and AutoCAD documents saved through a temporary file stay in their fence, and downloads in progress and Office lock files stay hidden. Rules with a double extension like `tar.gz`, or a name like `gitignore`, match their files.
- A rule added in Settings goes to the top of the list (#122). Rules go by first match, so a new rule at the end usually never got a file; `pecofence-cli rule add` still adds at the end. Snapshots you saved are no longer deleted when Settings saves its own once there are 20, and with the list full, restoring a snapshot or importing a configuration says so and changes nothing, where it ran without a snapshot to go back to.
- The fences come back on the graphics card after a graphics driver reset, where they stayed on slower drawing without it, and the welcome and rating notices are drawn again (#122). A moment of low memory no longer turns Liquid Glass off for good. With a Span wallpaper over several monitors each fence's glass shows its own part of the picture, Centre and Tile wallpapers show at their own size through the glass, and Fluent glass is no longer stretched where a fence leaves its screen. The 「详细信息」 view keeps dates, types and sizes inside their columns.
- Settings rescales when it is moved to a monitor with another scale, and when Windows refuses a change of 「随 Windows 启动」, the switch flips back and says so (#122). A switch between light and dark while a PecoFence dialog is open reaches the fences, a z-order set by `pecofence-cli` or an imported configuration applies without a restart, and turning off 「双击桌面空白处隐藏或显示栅栏」 while the fences are hidden shows them again.

## 0.2.1

- Tabs can stand in a column on the left of a fence (#72): set 「标签栏位置」 to 「左侧」 (Settings › 常规, or `pecofence-cli settings set tabBar left`) and a fence with two or more tabs lists them from top to bottom, one name per row, like the vertical tabs of Firefox and Edge, so many tabs no longer squeeze each other's names. The column is as wide as the longest name needs (96 to 160 DIPs) and takes the place of the title row: drag the fence by its empty part, double-click it or press the button at its bottom to roll the fence up, right-click it for the fence menu, drop another fence on it to merge them. Rolled up, the fence shrinks to the column alone, just tall enough for its tabs, its rounded corners kept through the animation; every tab looks the same there, and a click on one expands the fence back to its own size on that tab (the button at the bottom, the selection fill and the bold name of the tab shown last only appear while the fence is expanded). Switching, dragging to reorder (up and down), tearing a tab off (sideways), dropping files on a tab, the wheel and switching on hover all work in the column. When the column appears or gets longer, a fence too short to show every tab grows to fit, as far as the fence below it or the bottom of the screen. The default stays 「顶部」.
- The Store edition keeps its fences, settings and snapshots across restarts again when it is installed on another drive than %APPDATA% (Windows Settings › System › Storage › Where new content is saved › New apps), or %APPDATA% was moved to another drive (feedback #7, #19, #23). Windows refused to move the saved file into place there (`os error 17` in the log), so every start came back with the first-start fences and nothing changed since survived. PecoFence now writes `config.json` in place when that happens, keeping the previous one as `config.bak`.
- The Store edition installed on another drive (Windows Settings › System › Storage › Where new content is saved › New apps) keeps the log of the previous run again (found while reproducing feedback #23). Windows refuses to rename files in that edition's copy of %LOCALAPPDATA% there (`os error 17`), so every start emptied the log instead of keeping it as `pecofence.prev.log`, and a report sent after a crash and a restart had no log of the run that crashed. PecoFence now keeps a copy of the old log when the rename is refused.
- After a restart, shortcuts in the fences no longer stay a plain page icon (or Windows' blank program icon) instead of their own (feedback #11). PecoFence starts while Windows is still busy signing in: it can answer "not ready yet" for a shortcut's icon for longer than PecoFence waited, or hand back the blank icon while the drive a shortcut points to is not there yet, and that first answer stayed until the file changed or PecoFence restarted. Explorer's desktop shows the icons it remembered from last time meanwhile. After a start at sign-in, PecoFence now asks for every icon again half a minute, two minutes and ten minutes later and swaps in the ones that came back different; the log counts them.
- The fences follow live wallpapers such as Wallpaper Engine and Lively (feedback #24, and a report on linux.do). Those play their video or web page in a window over the Windows wallpaper, and PecoFence kept building its glass from the Windows wallpaper underneath, so Liquid Glass showed the old picture through the fences and Fluent took its colours from it. PecoFence now takes a picture of the live wallpaper and builds the glass from that: when the live wallpaper starts or changes, when the desktop comes to the front (a click on it, or Win+D), and once a minute while a fence on that screen is in view, not hidden behind a maximized or full-screen app. That picture stands still while the video moves, so on a screen with a live wallpaper Liquid Glass is frosted like Fluent instead of clear. Closing the live wallpaper brings back the glass made from the Windows wallpaper.
- Opening a file from a fence hands the program the name as it is spelled on disk (feedback #25). For `ABC.zip` the program was given `abc.zip` and showed that name, because PecoFence remembers each icon by its lower-cased path, so that it finds the file in any letter case, and opened that path. Each icon now also keeps its spelling on disk, which is used for opening (in folder portals too), for the paths `pecofence-cli` lists and for renaming: an icon whose extension Windows hides, renamed from 「SCAN」 to 「Bill」, becomes `Bill.PDF` instead of `Bill.pdf`. Finding files still ignores letter case.
- With 「隐藏 Windows 桌面图标」 off, Windows' own desktop icons work next to the fences again (feedback #20, #27). PecoFence took a press on one of them for a press on empty desktop: double-clicking an icon opened it and also hid all fences, and dragging an icon selected every fence its path crossed. A press on a Windows icon now starts no double-click hide and no box. Dragging the OneDrive (or user folder) desktop icon onto a fence no longer tries to move that folder and fails with "0x80004001 Not implemented"; it makes a shortcut to it, as dropping This PC does.
- 「隐藏 Windows 桌面图标」 stays on when hiding the icons fails at startup (feedback #20). When Explorer's desktop did not respond for half a minute after PecoFence started, PecoFence said 「无法隐藏桌面图标，请稍后再试。」 and also switched the setting off, so every later start left the Windows icons on the desktop as well as in the fences, although nobody had chosen that. It still shows the notice and stops trying for that run, but the setting stays on: the next start tries again, and so does turning the setting off and on.
- This PC and the Recycle Bin show the right icons in a fence and go where they are dropped (feedback #27). Once the Recycle Bin first filled, its icon stayed the empty bin for the rest of the session, because right after a file is recycled Windows still hands out the empty picture; it now switches between its full and empty icons (your own ones, if you changed them in Windows' desktop icon settings) as soon as PecoFence sees the change. An icon Windows could not hand over at that moment, as can happen to This PC right after PecoFence starts, stayed a blank page; it is now asked for again. And with the Windows desktop icons showing, dragging This PC or the Recycle Bin from the desktop onto a fence put the shortcut Windows makes (「此电脑 - 快捷方式」) into whichever fence the rules picked; it now goes into the fence you dropped it on.
- The Peek shortcut can be any combination you like (feedback #26). Two of the three choices, Win+Space and Win+Shift+Space, never worked on Windows 10 or 11, which keep them for the input switcher even with a single keyboard layout, and Settings kept showing them while Peek had quietly moved to another one. In Settings › 常规 › 速览栅栏, click the shortcut box and press a combination with Ctrl, Alt or Win; PecoFence takes it at once, or says that Windows or another app already uses it. 「包含 Win 键」 adds Win to the next combination, since Windows catches many Win shortcuts before Settings sees them. Combinations that would take common Windows functions away (Ctrl+Space, Alt+Space, Alt+Tab, Ctrl+C, Win plus one key, and the like) are refused. Ctrl+Alt+Space stays the default, Win+Alt+Space and Ctrl+Shift+Space replace the two Win+Space choices, and Settings now shows the shortcut that really works, with a note when the chosen one is taken. pecofence-cli sets it with `settings set peek.customHotkey Ctrl+Shift+F`. A configuration from 0.2.0 still opens, and 0.2.0 still opens one saved now (it uses Ctrl+Alt+Space there).
- With two Windows accounts signed in at the same time, `pecofence-cli` and a second start of PecoFence work in both (feedback #13). The named pipe the CLI talks through had one name for the whole computer, so in the account whose PecoFence started second the CLI was off (`pipe name unavailable; CLI disabled` in the log): pecofence-cli there failed with "Access is denied", or, run as administrator, reached the other account's PecoFence, and starting PecoFence again did not open its Settings. The pipe name now contains the account's SID (`\\.\pipe\PecoFence.<SID>`), so each account reaches its own PecoFence, also from another session of the same account such as an ssh login.
- PecoFence keeps less memory between uses. Half a minute after the fences last drew something, it hands the memory the last use touched back to Windows, every time instead of only once after startup; what it needs again comes back on its own, with no visible delay (the first animation after a pause measured the same as before). On a 4K monitor the memory Task Manager shows for PecoFence at rest stays at about 2 to 5 MB, where it used to grow to about 28 MB after some hours of use. Settings, Peek and a name being edited keep their memory while they are open.
- A report of PecoFence using far more memory than usual (a user saw 366 MB in Task Manager) can now say where it went. Task Manager's number only counts what sits in RAM right now, so the report's memory line also gives the memory PecoFence has reserved and its graphics memory (dedicated and shared), and the diagnostic log gets a memory line once an hour and whenever these grew by 64 MB, so the log shows when the growth happened and next to what.
- A crash inside another program's code, such as a graphics driver, can now be traced from the report it leaves (feedback #22). PecoFence 0.1.5 closed for a Store user while the AMD graphics driver redrew a fence, and the report showed only where in the driver it happened. The crash line in the log now also says whether the failing instruction read, wrote or ran code and at which address, and gives the file version of the module it was in and of pecofence.exe. A report sent from 「反馈」 also names the graphics adapter the fences are drawn on and its driver version (`gpu:`), without serial numbers or other identifying data.
- The box for a new name opens on top of the fence after Win+D (「显示桌面」) and during Peek (#99). The fences float above every other window then, and the rename box (F2, 「重命名」 in an icon's menu, or a fence title) opened behind its fence: through Fluent it showed only faintly under the old name, through Liquid Glass hardly at all, so renaming looked broken.
- Every tab switch and every fence fading in or out kept a little memory (about 0.3 KB) until PecoFence quit, roughly 1 to 10 MB over a week of use. It is now released when the animation ends.
- Changing a fence's icon size, spacing, label lines or view reuses the graphics memory the fence already has. Until now each change kept about one fence picture's worth of video memory until PecoFence restarted: on a 4K monitor twelve icon size changes added about 100 MB in Fluent and about 220 MB in Liquid Glass, and the total grew with every change. It now stays where the first change left it.
- When PecoFence's graphics memory still grows well past where it started (by more than 64 MB, for example after many resizes to new sizes or with Liquid Glass), it sets up its graphics anew half a minute after the last change, at most every five minutes. That takes about 0.07 s with Fluent and 0.3 s with Liquid Glass and changes nothing on screen, and the memory goes back to where it started. On integrated graphics this memory comes out of the computer's RAM.
- Photo thumbnails and icons no longer pile up in memory. PecoFence keeps the icons its fences show, in every tab and at the current icon size, and lets the others go a few seconds after a change: another icon size or screen scaling, a folder a portal has left, a fence closed or deleted, files deleted from the desktop. Ten folder portals of 300 photos each, opened and closed one after the other, used to leave about 190 MB in use for as long as the photos existed; now PecoFence is back at about 12 MB after each one. Going back into a folder reads its icons again, so a big folder of photos may show grey tiles for a moment.
- Liquid Glass keeps the wallpaper for its refraction at half the monitor's resolution, a quarter of the graphics memory it took: on a 4K monitor about 8 MB per wallpaper instead of 33 MB (two wallpapers when virtual desktops differ). The glass scales it back up with linear filtering, which looks the same through the glass; Center and Tile wallpapers keep their native scale, as the picture is still decoded at full size first.
- Icons dragged out of a fence onto empty desktop go back into 「桌面」 again, as intended (feedback #31). The glass fades in while the pointer is over the fence, while it is rolled up, floats (Peek), takes a drop or is selected with a desktop rectangle.

## 0.1.1

- Switching virtual desktops no longer blanks the fences: they slide out and in with the desktop, content and glass together, instead of disappearing for the whole animation and popping back afterwards. The other desktops' wallpapers are prepared in the background, so a fence already shows the new desktop's picture as it slides in (about 33 MB more per extra 4K wallpaper). During taskbar-thumbnail Aero Peek fences now fade like other windows.
- Less memory with Liquid Glass: on a 4K monitor with 7 fences the idle private working set drops from about 97 to 40 MB and GPU memory from about 200 to 80 MB. GPU caches are released once drawing goes quiet, the full-resolution wallpaper is kept only on the GPU, and fence shadows no longer hold their bitmap after it is shown.
- Fences no longer grow into each other: expanding a rolled fence, changing the icon size, auto height and the cell snap stop a snapping gap short of the next fence (the rest of the items scroll), and a dragged edge stops at a neighbouring fence. A fence dropped onto another one moves the shortest way to a free spot (an outline shows where while you drag), and overlaps a layout already has are pulled apart at startup (larger fences stay, smaller ones move; with no free spot a fence stays put) (#2).
- Changing a fixed-height fence's icon size fits its height to the content, so shrinking the icons no longer leaves rows of empty space (#2).
- Snapping settings now match Stardock Fences: 「移动栅栏时吸附对齐」 (keep fences lined up when moving), 「栅栏间距」 (space between fences, 0–32 px, back on the settings page) and 「调整大小时保持为整数个图标」 (`snapping.sizeToCells`, whole icon columns and rows, which was stored but did nothing). With it off (the default) a fence can be any size: the icon grid spreads its columns over the width, a fence keeps its width when the icon size changes (it used to grow or shift left) and a dragged side edge snaps to neighbouring fences' edges (#1, #2).
- Smoother icon edges: icons from the shell came with straight alpha but were drawn as premultiplied, which made anti-aliased outlines look jagged, most visibly at large sizes on dark wallpapers (#2).
- 「在桌面显示文件夹」 (Show a folder on the desktop) in the tray and fence menus shows Documents, Downloads, Pictures or any chosen folder as a live fence; the UI no longer says "portal".

Found by letting an agent organise a real desktop with the CLI:

- pecofence-cli: `item move --dry-run` (method `items.planMove`) lists per item whether only the icon changes fence (`membership`), a real file moves (`fileMove`, with `destination`), nothing happens, or it is skipped (`exists`, `notAFile`). The real move now skips files whose name already exists at the destination (`skipped` + warning) instead of opening Explorer's replace dialog on the user's screen, and says `fileMove: true` when files are still on their way.
- pecofence-cli: `fence get` / `fence list` report `fit` (columns, rows, the height that shows every item, `overflow`) for the fence each window shows; `fence fit <FENCE>` applies that height.
- pecofence-cli: when the app changes a rect on its own (auto height after `fence move/resize/fit` or `fence create --rect`, whole columns and rows after `fence set iconSize/spacing/layout/labelLines`), the reply carries `adjusted {requested, applied, reason}` instead of a silently different size.
- pecofence-cli: `fence create --below/--above/--right-of/--left-of <FENCE> [--size w,h]` places a fence next to another one with aligned edges and the snapping gap, refuses rects that leave the work area and warns about overlaps.
- pecofence-cli: global `--fields id,title,rect.w` keeps only those keys (no jq needed) and `--ascii` writes non-ASCII as `\uXXXX`, for readers that decode stdout with the ANSI code page (Python on a Chinese or Japanese system, Windows PowerShell 5).
- pecofence-cli: `item list` reports `shortcutArguments`, so the same program started with other arguments no longer looks like a duplicate.
- pecofence-cli: a folder portal that has been navigated into a subfolder reports it as `portal.current`; `item list` shows that folder and `item move` to the portal puts files there.
- pecofence-cli: a hosted tab's `rect` is now its host window's (it was the tab's stale own geometry, which made fences look overlapped); snapshots report `fenceCount` for the current monitors (it used to sum every monitor layout, e.g. 21 for 7 fences).
- pecofence-cli: the hint for a rule without conditions names `describe --schema Cond` (it named a command that does not exist).
- `snapping.gapPx` now sets the gap fences keep while snapping (it was stored but ignored; the gap was always 8 DIP). `snapping.sizeToCells` and `snapping.guideLines` are still unused; setting them over the CLI returns a warning.
