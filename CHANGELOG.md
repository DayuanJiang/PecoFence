# Changelog

## Unreleased

- Ctrl+V and Delete: the selection no longer turns grey for about five frames and then blue again. Windows takes the keyboard from the fence while it copies or deletes the files (about 0.3 s), so the box showed the grey of a fence without the keyboard; on the freely placed desktop the box of a pasted copy came, nearly went and came again. A fence now keeps its selection colour while a file operation of its own runs, and reads the real state again half a second after the operation is over.
- F2 on an icon: the name no longer goes blank for a frame before the name box shows. The fence drew the icon without its name first and the box was painted a frame later.
- A file renamed in place and confirmed by a click on an empty part of its fence glides to its new place in the sort order, as it does after Enter. It stood there in one frame (the click's rubber band, not yet moved, switched the motion off).
- Ctrl+X on an icon, then Esc: the cut is taken back, as on Explorer's desktop (the icon is whole again and still selected, the clipboard is empty; a second Esc ends the selection). Esc used to end the selection and leave the icon faded, with the file still on the clipboard. A click elsewhere leaves the cut as it is, as in Explorer.
- Ctrl+C, Ctrl+V on an icon: the selection box of the copy fades in with the copy. The copy faded in bare and its box stood there in one frame when the fade-in was over; on the freely placed desktop the box came, went for a frame and came again. (The box of an icon was drawn only once the icon was at full strength.)
- A new file's icon: name and picture come together. The name faded in at once and the picture two to three frames later (it comes from a background thread), in a fence and on the freely placed desktop. The fade-in now waits for the picture (167 ms at most, so a file whose picture takes longer still shows its name).
- The tip of an icon comes again when the pointer leaves the fence and comes back to the very same point. It stayed away until the pointer had moved by at least a pixel.
- Script fences: after a failed run the footer names the script in German, French, Spanish, Italian, Portuguese and Russian too. The status was so long there (German 「Fehler bei der Ausführung um 9:53 (Exitcode 1)」) that a fence 300 px wide left the script's name out; it now reads 「fail.ps1 · Fehler um 9:53 (Exitcode 1)」.
- The card after a fence is deleted says what happened first in every language, as the Chinese text does. In nine languages the verb came after the fence's name, so a long name pushed it onto a second line by itself (English: 「Fence “Quarterly reports and invoices 2026”」 and then 「deleted」; Japanese broke 「削除」 from 「しました」). It now reads 「Deleted fence “…”」, 「Bereich gelöscht: „…“」, 「フェンスを削除しました：「…」」; the manual shows the same.
- Japanese: the text of an empty fence is 「ここにドラッグ」. In a narrow fence (150 px) 「ここに項目をドラッグ」 wrapped and left its last character 「グ」 alone on a second line.
- Settings › 布局与备份: the description of the 「导出 / 导入配置文件」 card is one line in Simplified Chinese. Since descriptions are balanced over their lines it broke inside a word (「…迁移到另一台电」 and then 「脑；导入前会自动保存一份快照」); it now reads 「导出为 JSON 以便迁移到另一台电脑；导入前自动保存快照」.
- The notice after a crash inside ExplorerPatcher while a menu was built now tells both things. PecoFence then switches the Windows entries of the icon menus off, as after such a crash in any other program's file, but the notice only spoke of ExplorerPatcher's setting, so the entries were gone without a word. It reads 「右键菜单里的 Windows 菜单项已暂时关闭。先在 ExplorerPatcher 的 Properties 里取消“Register as shell extension”，再从托盘菜单恢复。」 and fits the banner in all 11 languages.
- Windows notifications: every notice of the app now fits Windows' banner in all 11 languages, and says first what to do, then why. The banner shows 4 lines (about 130 half-width characters; a Chinese, Japanese or Korean character counts two) and cuts the rest: 13 of the 36 notices were longer in at least one language (the one about a configuration file that another program holds open had 238 characters in French and 180 in English), so the end of the sentence, often the part that says what to do, was never shown. The new texts: 「请检查能否写入 C:\…\PecoFence：配置无法保存，退出后更改会丢失。」, 「请在设置里给“临时显示 Windows 桌面”换一个快捷键：Ctrl+Alt+D 已被系统或其他程序占用。」, 「“速览栅栏”改用 Ctrl+Alt+Space：快捷键 … 已被系统或其他程序占用。」, 「现在的更改不会保存：配置文件正被其他程序占用（可能是杀毒或同步软件）。读到它后，PecoFence 自动换回你的栅栏。」, 「请把 PecoFence 移到 C 盘（Windows 设置 › 应用 › 已安装的应用），或改用便携版：保存的设置读不出来（Windows 错误 409）。」, and the notices after a crash in another program's file or in ExplorerPatcher name the remedy first. A unit test holds every notification text to the limit in every language.
- Settings › 布局与备份: 「尚无每日备份」 has a second line too (a backup is made by itself on the first change of each day, the last 7 are kept), like the empty lists of rules and snapshots.
- Settings › 关于: a click on 「检查更新」 no longer makes the card's title jump. At rest the card shows 「更新」 alone; 「正在检查更新…」 then came under it and the title jumped up by half a line. The title now glides there and the status line fades in.
- Settings: an open drop-down list is never wider than the window. A fence with a very long name (up to 120 characters) made the lists of 栅栏 and of a rule's 「目标栅栏」 wider than the window, shifted to the left and cut at the right; the name now wraps inside the list.
- Settings › 整理规则: with no fence at all, the 「目标栅栏」 list of a rule is greyed out. It opened as an empty list.
- Settings: a description that wraps no longer leaves one character alone on its last line (整理规则 read 「…都不符合的放进“桌面”栅」 and then 「栏」 at the window's default size; in Japanese two descriptions on 常规 ended with a two-character line).
- 新建智能栅栏: the line that says how many files were found breaks into two lines of about one length when it needs two. In a narrow editor window it read 「填好条件后显示找到几个文」 with 「件」 alone on the second line, and in German and Russian the last word stood alone at the window's default size.
- Settings: the notice at the bottom of the page (「已保存快照」, 「撤销」) comes in decelerating and leaves accelerating, as everything that enters and leaves on the fences does. It moved on the browser's default curve in both directions.
- Settings › 关于: when 「检查更新」 fails, its card needs a second line and 「打开下载页」, and everything under it jumped down by 10 px. The cards under it now glide down (167 ms).
- Settings: empty lists say what to do, and the fence picker copes with no fence and with a long name. 「尚未添加规则」 and 「尚无快照」 now have a second line (pick a kind under 「快速添加」 or write a rule under 「新建规则」; 「保存快照」 keeps the layout as it is now). With no fence left, 栅栏 showed an empty drop-down list beside 「0 个栅栏」: the picker is gone there and the card that says how to make a fence stands alone. A fence with a very long name made the picker as wide as the page, pushed the number of fences onto a second line and ran its text under the list's arrow: the picker is now at most 460 px wide and the name ends before the arrow.
- Settings and the smart fence editor: the controls that did not answer the pointer now do. A text box (and the box of 查找设置) lightens under the pointer as Windows' own do; the selected page in the navigation, the highlighted row of the 查找设置 list and the chosen option of an open drop-down list get a stronger tint under the pointer and a weaker one while pressed (they looked the same at rest, under the pointer and pressed); every row of those two lists has a pressed look. Found by going through all 102 kinds of control on the seven pages and in the editor for their look at rest, under the pointer, pressed and with the keyboard's focus, in 浅色 and 深色.
- Settings: dragging the window narrower or wider no longer makes the navigation jump. Its width stepped from 240 to 200 px at a window width of 900 px and to 172 px at 740 px (the cards jumped 52 and 28 px to the side with it), and at 540 px it folded to its icons in one frame. Now between 740 and 900 px the navigation, its rows and the page's margins follow the window's width, and the fold to icons at 540 px glides (167 ms; with Windows' animations off it is one step, as before).
- Settings and the smart fence editor: on a change of 颜色模式 (or of Windows' own mode with 跟随系统) the title bar changes colour together with the page. The title bar was set at once and the page a frame or two later, so for a moment a light title bar stood over the dark page, or the other way round. Now the title bar waits for the page to say that it draws the new colours (a quarter of a second at most). In a test VM without a GPU the title bar was ahead of the page in 5 of 22 recorded switches before and in none of 42 after; in 2 of the 42 it is now one recorded frame behind.
- Settings' small animations run at the fences' four speeds (83, 167, 250 and 333 ms) and on their curves. The page had times of its own beside them: 150 ms for the switches and the fade of a button under the pointer, 120 ms for the dot of a 主题风格 tile, 100 ms for a slider's thumb, 180 ms for the notice at the bottom, 200 ms for the preview's icons and 800 ms for the tint of a setting found by 查找设置. Now a button's fill fades in 83 ms as Windows' own buttons do, a switch slides in 167 ms, and the rest take the nearest of the four; with Windows' animations off nothing moves, as before.
- 「退出 PecoFence」 no longer leaves the desktop empty for a moment. The fences faded out in 167 ms, but File Explorer shows its own icons only about a third of a second after it is asked (343 ms measured with 45 icons), so the bare wallpaper showed in between (306 to 337 ms in the test). The fences now stay for 400 ms and then fade, so the Windows icons are back before the last fence has gone. With Windows' animations off nothing waits.
- 「退出 PecoFence」 no longer leaves the desktop empty for a moment. The fences faded out in 167 ms, but File Explorer shows its own icons only about a third of a second after it is asked (343 ms measured with 45 icons), so the bare wallpaper showed in between (306 to 337 ms in the test). - The offer 「让新文件自动进来」 is no longer lost while the card 「栅栏多了可以收起」 is on screen. Three files of one kind dragged into a fence right after it was made (when that card shows for 30 seconds) were counted, but the offer was dropped and came back only with a fourth such file. The offer (and 「把常用的文件夹放到桌面上」) now takes that card's place.
- The card 「栅栏多了可以收起」 waits until the new fence has its name. It came up beside the name box the instant the fence appeared, while the name was still to be typed; it now shows when the name box has closed.
- After a Peek that was opened from the desktop is closed with Esc, the shortcut or a click beside the fences, the keyboard is back on the desktop. Windows gave it to the taskbar when the Peek's window went, so the arrow keys moved through the taskbar's buttons and Tab did not reach the desktop's icons.
- A tip card on screen follows a change of the display language. After 「显示语言」 was changed while a first-start tip showed, the fences took their names in the new language but the card stayed in the old one until 「下一条」 was pressed.
- After a Peek, no icon keeps the keyboard focus ring. Tab or the arrow keys during a Peek put the ring on an icon; when Esc ended the Peek the ring stayed, although the keys went to the window in front, so the fence looked as if it still had the keyboard.
- 「检查更新」 works where GitHub's API cannot be reached. The check (the button on Settings › 关于 and the automatic one) asked only api.github.com; on networks that cannot reach it, common in China, the button said 「检查更新失败，请稍后再试」 after a wait of up to a minute, and the automatic check never found a new version. Now a check without a good answer from GitHub within 8 seconds (no connection, an error, a rate limit) asks the PecoFence website for its copy of the latest release (`pecofence.jiang.jp/update.json`) and offers the version from there; its download button then opens the site's download page. When neither answers, the page says 「没能连上 GitHub 和 PecoFence 网站，检查不了更新。请稍后再试，或到 pecofence.jiang.jp 下载最新版本。」 and shows 「打开下载页」 beside 「检查更新」 (a failed download of the setup says the same about the download); the automatic check stays silent as before.
- The update card shows the new version's first note on networks that reach GitHub's API but not its file server (raw.githubusercontent.com), which is common in China: the line is then read from the website's copy of the release. The card said only 「看看这次更新了什么。」 there.
- 「更新」 on the update card or in the tray menu no longer fails without a word. When the new setup could not be downloaded, nothing showed unless Settings happened to be open on 关于. Now Settings opens on 关于, says 「没能下载新版本。请稍后再试，或到 pecofence.jiang.jp 下载最新版本。」 and offers 「打开下载页」.
- 「更新」 on the update card or in the tray menu says that it started: a notification 「正在下载新版本…」 shows, and until setup starts the first item of the tray menu reads 「正在下载新版本…」 instead of 「更新到 …」. Before, nothing showed while the setup downloaded, which can take minutes on a slow connection to GitHub, and a second click did nothing.
- A folder fence remembers the view and the sort order of each folder, as File Explorer does (feedback #131). There was one view and one order per fence: 「详细信息」 by date chosen inside a subfolder was also what the fence's own folder and every other subfolder showed afterwards. Now a change made inside a subfolder (视图, 排序方式, 倒序, 文件夹优先, 按时间分组) stays with that folder: one level up the fence shows its own view and order again, and the subfolder opens the way it was left, also after a restart. A folder that was never changed takes the fence's own view and order. The fence menu, Settings › 栅栏 and `pecofence-cli fence get / set` show and change the folder on show. A fence keeps this for the last 50 folders that differ from its own (`folderViews` in the configuration); icon size, spacing and column widths stay one per fence. The same holds for a folder opened inside an ordinary fence.

- To-dos in a note without typing `[ ]` (feedback #141). Every to-do had to start with a hand-typed `[ ]`, and Enter in a to-do gave a plain line. Now Enter in a to-do starts the next line with an empty check box, Enter in a to-do that has no text yet takes the box away again (Shift+Enter is a plain line break), and the note's menu has 「添加待办」: it adds an empty to-do after the last line and puts the caret in it.

- With Windows' 「通过单击打开项目（指向时选定）」, pointing at an icon selects it in whichever fence is under the pointer, and F2 renames it (#184). The icon was selected only in the fence that already had the keyboard: coming from the desktop or from another fence nothing was selected, and F2 went to the desktop. Now the fence under the pointer selects after Windows' hover time and takes the keyboard while it, another fence or the desktop has it (another program in front keeps it, as over the desktop), and the selection in the other fences ends. During a Peek pointing selects in every fence too (it did in none, since no fence is the active window then), and the keys go to that fence. F2 while the pointer is on a fence's title, with no icon selected in it, opens the fence's name box (the tab's, over a tab): click the title first, or with single-click open just rest the pointer on it. With single-click open, where pointing is selecting, F2 on the title renames the fence also while an icon selected earlier is still selected in it.

- A folder fence notices that its folder was renamed, moved or deleted as soon as the pointer comes onto it. It could go on showing the folder's old icons for up to a minute (the check ran once a minute), and whatever was done with them failed. Now the fence says 「找不到此文件夹。」 the moment the pointer arrives, and while it says so it takes no dropped files: a file dragged onto it gets the 「禁止」 cursor and stays where it was, where it used to end in a Windows notification with a system error (「移动到文件夹失败：… (0x80070002)」).
- Going into a subfolder of a folder fence, or back up, the title changes with the icons. The name and its glyph (the folder, or the up arrow) cut to the new folder's in one frame, while the icons under them were still the old folder's and then cross-faded. The name and glyph now fade in over the same 83 ms, in a single title and in a folder tab alike (the tab keeps its pill, in the title row and in the left tab column). With Windows' animations off everything still changes at once.
- The tips of a folder fence's title glyph say which folder the fence shows. The title is one name: the fence's own at the root (after a rename it differs from the folder's), the subfolder's below it, and nothing said which folder that is or how deep the fence has gone. The tip of the folder glyph (「在资源管理器中打开文件夹」) and the tip of the up arrow (「向上」) now end with a second line: the path of the folder shown.
- A tab dragged along the strip shows one name. Its fill is see-through, so while it passed over a neighbour both names were drawn on top of each other (「工作」 over 「图片与设计稿素材」) until the neighbour slid away. What the dragged tab covers is no longer drawn under it, in the title row and in the left tab column, as a tab dragged in File Explorer hides what it passes over.
- A tab split out with 「拆出为独立栅栏」 no longer lands on top of the window it left while the loose icons are arranged like the desktop (the default of a new install). The window of those icons reaches from the first icon to the last, often over the whole screen, and it counted as a fence in the way: no place was free, so the fence opened centred on its old window. The same went for every new fence PecoFence places itself (「新建栅栏」 and 「在桌面显示文件夹」 in the tray and fence menus). The loose icons make way for a fence, so their window no longer counts: a split-out tab goes back where the fence stood before it was merged, or beside the window it left.
- A folder fence whose folder was renamed, moved or deleted no longer puts up Windows' own error box, and shows the folder again as soon as it is back. For up to a minute such a fence went on showing the folder's icons; a double-click on one of them, or a click on the folder in the title, then opened a box 「Windows cannot find …」 in the middle of the screen, and until it was closed no fence reacted to anything. The fence is now read again at that moment and says 「找不到此文件夹。」. A fence that learned this way, or from a file dropped on it, that its folder is gone also looks for it every 1.5 seconds like any other: it stayed empty for up to a minute after the folder had come back.
- Ctrl+Z takes back a merge into tabs and a tab that was pulled out. A fence let go on another fence's title became a tab there, and Ctrl+Z did nothing (the step was used up all the same), so a merge by mistake had to be undone by hand. After a tab was dragged out, Ctrl+Z moved the new fence on top of the window it had left and kept it a fence of its own. Now Ctrl+Z after a merge (by drag, or with 「合并到…」 in the tab menu for a fence that had a window of its own) puts the fence back where it stood, with the tabs it had brought, and Ctrl+Z after a tab was dragged out (or split out from the tab menu) returns it to its window at its place in the strip, also when the same drag had dropped it on another fence. A tear-off cancelled with Esc is no step.
- When the configuration file was held open by another program at start and turns out unreadable once it can be opened, the notice says so and names the backup that shows instead. It said 「已读到配置文件，你的栅栏已恢复。」 although PecoFence had fallen back to config.bak or a daily backup.
- A snapshot saved without a name gets a name no other snapshot has. The name was 「快照」 plus the number of snapshots, so after a delete two snapshots could both be 「快照 2」, and `pecofence-cli snapshot restore` by that name found two.
- pecofence-cli: `rule import` warns when rules of the list point to a fence that does not exist or cannot hold desktop icons (a folder, tool or smart fence). The list was stored without a word and the files those rules matched went to 「桌面」; only `config check` said so.
- Settings › 布局与备份: the snapshot list marks the snapshots PecoFence saved by itself (「恢复快照前」, 「删除栅栏前」, 「导入配置前」, 「恢复备份前」 and the command line's `auto-cli-…`) with 「自动保存」 after the date and the fence count. They looked like the ones you saved, although only they are replaced when the list is full.
- 「立即应用整理规则」 with nothing to move says so: 「没有需要整理的项目，图标都已按规则放好。」, from the tray menu and in Settings. It said 「已按规则整理 0 个项目。」, which read as if something had gone wrong.
- Restoring a snapshot from Settings can be taken back with one click. The notice 「已恢复快照」 now stays for 6 seconds with 「撤销」: the layout from before the restore comes back and the automatic 「恢复快照前」 snapshot goes again. Before, the notice was gone after 2.4 seconds, Ctrl+Z on a fence did nothing, and the way back was to find 「恢复快照前」 in the list and restore that.
- Fences glide to their places when a snapshot is restored or a configuration is imported. A fence that came back faded in and one that went faded out, but a fence that had only been moved was at its old place in one frame and at the saved place in the next. It now travels there in 167 ms like a fence dropped on another one; a fence whose size or roll state changes with the restore is still placed at once, and so is every fence with Windows' animations off.
- Icons that leave a fence fade out, and icons that arrive fade in, however many they are. A fence animated a change only when at most half of its icons changed: after 「立即应用」 a fence that was empty faded its new icons in while the fence next to it, which already held a few, showed them in one frame, and 「撤销」 (or anything else that took most icons out of a fence) cut them away in one frame, with 「将项目拖到此处」 in their place at once. Now a change that only takes icons away or only brings icons in always animates (83 ms out, 167 ms in, the icons that stay glide to their cells), and the empty hint waits until the last icon has faded. A tab switch, a folder opened in the fence and the filter box swap the whole list as before.
- The notice of an unreadable configuration says what you see now. For a damaged config.json it guessed 「可能是较新版本的 PecoFence 写入的」 and only named the renamed file, so nobody could tell where the fences on screen came from. It now says 「配置文件读不出来，现在用的是备份 config.bak」 (or the daily backup's name, or that the default fences show) and that the unreadable file is still in the configuration folder under its new name; the guess about a newer version stays for a file that really names a newer format.
- While another program holds the configuration file open, 导入…, 导出… and a backup's 「恢复」 (and `pecofence-cli config import`, `config export`, `backup restore`) say that they cannot run now. Before, an import said 「已导入配置」 and was gone as soon as the file could be read, and an export wrote the stand-in fences that show meanwhile.
- When a restore or an import does not run because all 20 snapshots are your own, the notice says that nothing was changed (it only said that no new snapshot was saved).
- An import or a backup restore keeps this PC's search history (which files you open most from the Peek search box); exports never carried it, so every import emptied it.
- No 「无法保存配置，退出后更改会丢失」 notice when only the day's backup copy could not be written. config.json was saved with every change in that case (a read-only `backups` folder, a file in its place), so the notice was untrue; the log gets a line instead.
- A sorting rule can no longer point to a smart fence. The list leaves smart fences out, the command line refuses them, and a rule that already points to one says 「桌面」, where its files go.
- A configuration without a 「桌面」 fence gets one when it is loaded or imported. `pecofence-cli config check` said so for such a file (one edited by hand or by a script), but the app did not add it: files that no rule matched were then in no fence, and with Windows' own desktop icons hidden they showed nowhere.
- Restoring the 「删除栅栏前」 snapshot no longer takes your notes back to older text. The snapshot saved when a fence is deleted from its menu kept the text of every note and the settings of every script fence, so restoring it later put all of them back to what they were at the moment of the delete. It now brings back the deleted fence (a deleted note with its text) and leaves the other notes and scripts as they are.
- pecofence-cli: with 20 snapshots stored, `snapshot restore`, `fence delete`, `rule apply`, a large `item move`, `config import` and `backup restore` still take their safety snapshot when the list holds an automatic one of the settings page (「恢复快照前」, 「删除栅栏前」, 「导入配置前」, 「恢复备份前」): the oldest automatic snapshot gives its place, as on the settings page. Before, they went on without a snapshot and only warned. A list of 20 snapshots you saved yourself is still left alone.
- Undoing an import or a backup restore brings the icons back with the fences. Restoring the 「导入配置前」 or 「恢复备份前」 snapshot showed the fences from before, but empty: the import had replaced the list of desktop items, and the snapshot named icons that were no longer in it. After a file from another PC every fence was empty, after an older backup of the same PC the files added since were gone from their fences, and the rules then filed all of them again. The imported items now keep this PC's records, so the snapshot puts every icon back where it was.
- Restoring a layout snapshot no longer hides the files that came to the desktop after it was saved. Such a file was in none of the restored fences, so with Windows' own desktop icons hidden it showed nowhere until something else changed on the desktop (up to a minute, or longer with the icons shown). They are now filed by the rules at once, as after an import.
- The 「新建栅栏」 and 「在此显示文件夹…」 buttons fade out after a click (167 ms) while the new fence fades in; they vanished in the frame of the click.
- 「退出 PecoFence」 fades the fences out (167 ms) while Windows brings its desktop icons back. They were cut off in one frame and the desktop then stayed empty for about a quarter of a second (267 ms in the test, now 152 ms after a fade). The end of a Windows session still closes them at once.
- The name box of a new fence opens sooner. It waited until the whole entrance of the fence had been reported (about 0.3 s after the click, 316 ms in the test), and what was typed until then went nowhere. It now opens as soon as the fence has faded in (167 ms).
- Ctrl+Z right after 「新建栅栏」 takes the new fence away again (while it is still empty). A new fence had no undo step of its own, so Ctrl+Z undid whatever came before it: a fence moved earlier jumped back and the new fence stayed.
- At a start the desktop is no longer empty for a moment. - Security: text from the network can no longer make a script fence row that starts a program. Since 0.3.0 a script fence reads each printed line as `text | key=value`, and it could not tell the script's own parameters from text the script only passed on. Closing the live wallpaper brings back the glass made from the Windows wallpaper.
- Opening a file from a fence hands the program the name as it is spelled on disk (feedback #25). For `ABC.zip` the program was given `abc.zip` and showed that name, because PecoFence remembers each icon by its lower-cased path, so that it finds the file in any letter case, and opened that path. Each icon now also keeps its spelling on disk, which is used for opening (in folder portals too), for the paths `pecofence-cli` lists and for renaming: an icon whose extension Windows hides, renamed from 「SCAN」 to 「Bill」, becomes `Bill.PDF` instead of `Bill.pdf`. A press on a Windows icon now starts no double-click hide and no box. In Settings › 常规 › 速览栅栏, click the shortcut box and press a combination with Ctrl, Alt or Win; PecoFence takes it at once, or says that Windows or another app already uses it. 「包含 Win 键」 adds Win to the next combination, since Windows catches many Win shortcuts before Settings sees them. PecoFence 0.1.5 closed for a Store user while the AMD graphics driver redrew a fence, and the report showed only where in the driver it happened. Until now each change kept about one fence picture's worth of video memory until PecoFence restarted: on a 4K monitor twelve icon size changes added about 100 MB in Fluent and about 220 MB in Liquid Glass, and the total grew with every change. It now stays where the first change left it.
- When PecoFence's graphics memory still grows well past where it started (by more than 64 MB, for example after many resizes to new sizes or with Liquid Glass), it sets up its graphics anew half a minute after the last change, at most every five minutes. That takes about 0.07 s with Fluent and 0.3 s with Liquid Glass and changes nothing on screen, and the memory goes back to where it started. - Photo thumbnails and icons no longer pile up in memory. PecoFence keeps the icons its fences show, in every tab and at the current icon size, and lets the others go a few seconds after a change: another icon size or screen scaling, a folder a portal has left, a fence closed or deleted, files deleted from the desktop. Going back into a folder reads its icons again, so a big folder of photos may show grey tiles for a moment.
- Liquid Glass keeps the wallpaper for its refraction at half the monitor's resolution, a quarter of the graphics memory it took: on a 4K monitor about 8 MB per wallpaper instead of 33 MB (two wallpapers when virtual desktops differ). Explorer's desktop took such a drop itself: This PC and the Recycle Bin left a 「此电脑 - 快捷方式」 or 「回收站 - 快捷方式」 behind, which the rules then filed into 「程序」, so This PC showed up there once more after every drag; a file brought up Explorer's "The source and destination file names are the same" dialog, the fences did not respond until it was closed, and the icon stayed where it was. PecoFence now ends such a drag itself when it is released on empty desktop, with the Windows desktop icons hidden or shown. Holding Alt still makes a shortcut there, a file dropped on a folder icon Windows shows on the desktop still moves into that folder, and This PC dropped on a folder in Explorer still makes a shortcut in it.
- The fences show the wallpaper through Fluent and Liquid Glass again when the picture file it was set from no longer exists (feedback #35). Some wallpaper apps set the wallpaper from a temporary file and delete it afterwards, and a picture can be moved or deleted after you chose it. Windows keeps showing its own copy, but PecoFence could only read the original file, so the fences got a plain backdrop and the styles looked broken (`wallpaper unavailable at startup` and `backdrop refresh deferred until wallpaper is readable` in the log). PecoFence now builds the backdrop from the copy Windows keeps, and still follows every new wallpaper.
- With 「调整大小时按整行整列对齐」 on, the icons stay put while a fence is resized (#118). A height that is not a whole number of rows, as when an edge lines up with another fence, used to share the extra height out between the rows, so the icons jumped up and down each time the dragged edge passed another fence's edge. The rows now keep their spacing: the extra height stays empty under the last whole row, and a row that would only show in part is cut off there, so the fence still shows whole icons only.

- Documents saved in Word, Excel or PowerPoint stay in their fence. These programs save by renaming the document to a temporary name and a fresh copy to the document's name, and the document used to drop out of its fence and be filed again by the rules on every save.

- Importing a configuration or restoring a backup shows the files of its folder portals right away. A restored portal used to stay empty until something changed in its folder.

- With the right mouse button set as the primary button, double-clicking the desktop (quick hide) and dragging on it (selecting fences, drawing a new fence) use that button.
- Files copied onto a fence all land in it when the copy takes longer than 15 seconds. The later ones used to go where the rules put them.

- pecofence-cli: `fence create --portal` resolves a relative folder such as `.` against the current directory, not PecoFence's.
- PecoFence closes when Windows asks it to: for a Store update, an installer, or the end of the session. It used to keep running, so Windows waited, ended it by force and reported it as not responding. After an update, PecoFence starts again by itself.

## 0.1.2

- Liquid Glass reworked after kube.io's refraction model: the face of a fence stays perfectly clear and all the bending sits in the rim, where a convex squircle bezel refracts the wallpaper with Snell's law (index 1.5). The very edge mirrors the backdrop like thick glass, and the magnification eases out over 40 DIP so no inner frame shows between the rim and the clear face. A thin specular ring is filled with the refracted wallpaper's colour, strongly saturated. The old material's whole-panel warp, blur and colour fringes are gone, and Liquid Glass corners are now 16 DIP. Moving a fence draws faster (one displacement pass instead of three), and GPU memory peaks lower while arranging fences (about 160 instead of 450 MB with 7 fences on a 4K monitor).
- Fences line up when resized, whatever their icon size, spacing or view: a dragged edge, top and bottom included, snaps to other fences' edges (level, or a gap apart) and to the work area's edges, with alignment guides, also with 「调整大小时保持为整数个图标」 on. Away from them that option still sizes to whole columns and rows; at a height of no whole rows the rows share the space left over like the columns share the width, so a fence still shows whole icons only. Dragged edges, expanding a rolled fence and the automatic size changes stop exactly a gap short of the next fence instead of a whole row short. Switching the option on, a late DPI change at logon, tab changes and restoring a layout no longer re-round sizes; changing a fence's icon size, spacing, view or label lines still does (#1).
- Tab names no longer vanish on a narrow fence: squeezed tab pills give up their padding (down to 8 DIP) before a caption is shortened with an ellipsis.
- Alignment guides while dragging (「显示对齐参考线」, `snapping.guideLines`, on for new configurations): thin white lines along the edges a moved or resized fence lines up with, and along the screen's centre line when it snapped there.
- Dragged fences also snap to the screen's centre lines (centred horizontally / vertically on the work area). Holding Alt while dragging or resizing moves freely, without snapping.
- When a dragged fence's title is over another fence's title, that fence gets the white outline: releasing there adds the dragged fence to it as a tab. The outline used to disappear in that spot, which looked like a glitch.
- The drop outline no longer stays on screen after a Liquid Glass drag is cancelled with Esc or a right-click, and no longer flashes on top of the dragged fence every two seconds (the desktop-layer check took it for a foreign window).
- The 「在此新建栅栏」 menu that appears after drawing a rectangle on the empty desktop closes again when you click elsewhere or press Esc. It used to stay open until its item was chosen, and rectangles drawn meanwhile queued up more of them.
- The settings window follows Windows 11 Settings: neutral colours, plain 20 DIP icons, 14 / 12 px text and On / Off captions beside every switch; the slogans, the banner picture and the tinted sidebar are gone. Fluent and Liquid Glass are picked from two preview tiles that show the icon size, tint and Chameleon settings live. Icon tint and fence tint are colour swatches; alignment guides and the Peek hotkey sit under the switch they depend on and turn grey while it is off. Rules are one compact row each, the quick-add templates are chips inside their card, and the new-rule form opens on demand. The fence picker heads the 「栅栏」 page, and restoring the desktop icons moved to 「故障排除」 on the About page. Chinese, Japanese and Korean text in the window uses the font of the interface language, and 「显示语言」 is listed under 「外观」 again.
- Chinese file names and titles in fences are drawn with Microsoft YaHei UI. They used to come out in the Japanese UI font, with Japanese forms of shared characters (今, 令, 骨, 直) next to YaHei for simplified-only ones. Like Explorer, fence text follows the Windows display language: Traditional Chinese uses Microsoft JhengHei UI, Japanese Yu Gothic UI, Korean Malgun Gothic, every other language YaHei.
- Select several fences by drawing a rectangle on the empty desktop: every fence it touches is selected as you draw (Ctrl or Shift adds to the selection) and gets a white outline, like the other drag feedback. Drag any selected fence by its title and the whole group moves along, keeping its layout; the group's outline snaps to the other fences and the screen edges, Esc or a right-click puts it back. A click on the desktop or on any fence ends the selection. While the desktop icons are hidden PecoFence draws the selection rectangle itself, in white too (Explorer shows none then). A rectangle that touches no fence still offers 「在此新建栅栏」, and a drag that activates the desktop from another window now counts too.
- 「鼠标悬停时才显示标题栏」 no longer leaves an empty band at the top of every fence: at rest the title row folds away and the glass starts at the icons; when the pointer arrives, the glass grows back up and the title fades in, with the icons staying where they are. The shadow and the rounded corners follow the glass.
- 「标题对齐」 (Settings › General › Appearance, `titleAlign`): fence titles and tab strips can be left-aligned, centred like in Stardock Fences, or right-aligned. Centred titles are centred on the whole fence and keep clear of the roll-up chevron.
- 「全透明」 opacity (fence options, `opacity transparent`): no glass, tint, border or shadow at rest, only icons and titles, whose text picks dark or light ink from the wallpaper and gets a halo. The glass fades in while the pointer is over the fence, while it is rolled up, floats (Peek), takes a drop or is selected with a desktop rectangle.

- Switching virtual desktops no longer blanks the fences: they slide out and in with the desktop, content and glass together, instead of disappearing for the whole animation and popping back afterwards. - Fences no longer grow into each other: expanding a rolled fence, changing the icon size, auto height and the cell snap stop a snapping gap short of the next fence (the rest of the items scroll), and a dragged edge stops at a neighbouring fence. With it off (the default) a fence can be any size: the icon grid spreads its columns over the width, a fence keeps its width when the icon size changes (it used to grow or shift left) and a dragged side edge snaps to neighbouring fences' edges (#1, #2).

- pecofence-cli: `item move --dry-run` (method `items.planMove`) lists per item whether only the icon changes fence (`membership`), a real file moves (`fileMove`, with `destination`), nothing happens, or it is skipped (`exists`, `notAFile`). The real move now skips files whose name already exists at the destination (`skipped` + warning) instead of opening Explorer's replace dialog on the user's screen, and says `fileMove: true` when files are still on their way.

- pecofence-cli: global `--fields id,title,rect.w` keeps only those keys (no jq needed) and `--ascii` writes non-ASCII as `\uXXXX`, for readers that decode stdout with the ANSI code page (Python on a Chinese or Japanese system, Windows PowerShell 5).

- pecofence-cli: a hosted tab's `rect` is now its host window's (it was the tab's stale own geometry, which made fences look overlapped); snapshots report `fenceCount` for the current monitors (it used to sum every monitor layout, e.g. 21 for 7 fences).
