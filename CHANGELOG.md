# Changelog

## 0.2.4

- The fences no longer hide by themselves after 刷新 in the desktop's right-click menu (feedback #95), or after one click on the empty desktop right after using a fence. When the desktop came to the front, PecoFence took the press that brought it there for the first click of a double-click on the empty desktop, as it has to after a click from another program's window, which it does not see. But Windows 11's menu gives the desktop back when the button comes up on 刷新, so a double-click on 刷新, or another click there right after, completed a double-click and hid every fence. After using a fence, PecoFence saw that same press once more and could count it twice. Now only a press on the desktop that is still held when the desktop comes to the front counts; a double-click on the empty desktop still hides and shows the fences, also from another program's window.
- Fences keep their size when PecoFence moves them onto a screen with another scale (feedback #96). With a laptop at 125 % and an external monitor at 100 %, a fence PecoFence put on the other screen (after the screens changed, or with `pecofence-cli fence move`) was scaled by Windows a second time after PecoFence had already sized it for that screen: it came out a quarter larger on the laptop or a fifth smaller on the external monitor. So when the laptop screen came on again after the external monitor had been used alone, four fences in a row along the top of the laptop overlapped one another, and the next drag saved the wrong size. A rolled-up fence kept the title row height of the screen it came from and could save a shrunken spot, and a title drag onto the other screen cancelled with Esc put a Liquid Glass fence back at the wrong size (with Fluent, a group of fences selected on the desktop came back right, but the dragged one grew by a quarter at its next move). A fence dragged onto the other screen still takes that screen's scale, as before.
- The icons that are in no fence can stand on the desktop like Windows' own (feedback #93, #152, #158, and the requests to keep the Recycle Bin on the desktop): 「像桌面一样排列」 in the 「桌面」 fence's menu (or `pecofence-cli fence set inbox desktopLayout true`) takes away its title row, glass and edges, and its icons stand down columns from the top-left corner of the monitor, with white names, as with Windows' 「自动排列图标」. Cells under another fence stay free, so the icons flow around the fences, and a click on the empty desktop beside them reaches the Windows desktop (its right-click menu, for one). Each icon still shows once: dragged into a fence it leaves the desktop, dragged out of a fence onto the desktop it joins the columns. Drawing a rectangle on the empty desktop selects the icons it touches, as on the Windows desktop. While 「隐藏 Windows 桌面图标」 is off, Windows shows these icons itself, so 「桌面」 does not show them a second time; a 「桌面」 with tabs stays a fence. Turned off, 「桌面」 is a fence again, back where it was. New configurations start with it on (the Recycle Bin and the other unsorted icons stand on the desktop at the first start); a configuration made before keeps 「桌面」 as a fence until you turn it on in the menu or in Settings › 栅栏.
- The 「列表」 and 「详细信息」 views get larger with Windows' text size (requests on appinn). Their names, dates, types, sizes and column captions were always 12 px in 28 px rows, so Settings › Accessibility › Text size enlarged Explorer's rows and the item names in the icon view but not these rows. They now use the font of the item names in the icon view: at 125 % and 150 % the text is 15 and 18 px, the rows and the details header are 32 and 36 px tall (Explorer's rows are 31 and 36), and the details columns and the icons keep their size, as in Explorer (a value too long for its column ends in …). The box for renaming an item grows with the text as well. The fences change as soon as the new text size is applied, and at the default text size they look as before. A custom theme's `labelFont`, `labelFontSize` and `labelFontWeight` now set this text too.
- With a larger Windows text size, item names in the icon view are as large as on the desktop and in Explorer. PecoFence enlarged them twice: Settings › Accessibility › Text size already makes the desktop's icon font larger (15 px instead of 12 at 125 %), and PecoFence multiplied that by 125 % again, so names were 19 px at 125 % and 27 px at 150 %. A custom theme's `labelFontSize` still grows with the text size.
- The icons of a fence can sit in the middle (suggested by @jewind in #154): with 「图标对齐」 in Settings › 栅栏 › 布局 set to 「居中」 (or `pecofence-cli fence set <fence> iconAlign center`), a row of icons that does not fill the fence width, the last, shorter row too, sits in the middle with the width left over split on both sides. Clicks, renaming, the selection rectangle, the arrow keys and the insertion mark of a drag follow the icons, also in folder fences and tabs. It applies to the icons view; list and details rows are not affected. Each fence keeps its own choice and starts at 「左对齐」, so no fence changes until you pick 「居中」.
- A 「游戏」 quick option in Settings › 整理规则 › 一键创建栅栏并添加规则 (feedback #83) creates a 游戏 fence and puts game shortcuts in it, apart from the other programs: the desktop shortcuts Steam and the Epic Games Launcher make (`.url` files that start a game through `steam://rungameid/` or `com.epicgames.launcher://apps/`) and shortcuts to a program in a `steamapps\common`, `Epic Games` or `XboxGames` folder. It adds one 「快捷方式目标包含」 rule per kind of shortcut, so each shows in the rule list and can be turned off or deleted on its own, and another game folder can be added the same way.
- A rule value typed in quotes works (feedback #89): `"my report"` or `'my report'` as the 「条件值」 of a new name rule is saved as `my report`, so names with spaces match. The quotes became part of the text to look for, and no file name has them, so the rule never matched. The field now says that spaces need no quotes; in 「完整文件名」 each name may have quotes of its own.
- A restored snapshot gives every fence the roll state and height it had in the snapshot (feedback #76). A fence rolled up a moment before the restore, while its roll was still moving (a script running `fence roll` and then `snapshot restore`, for one), rolled up again after the restore and saved that, and a fence rolled up since the snapshot opened to the height it had last instead of the snapshot's. The windows now take the restored state at once, also after an import, a display change or 「交换两个显示器上的栅栏」.
- While you drag a file out of a fence during Peek, the dimming fades away, so the window you drag it to (a browser's upload area, a folder, a mail) shows as it is (feedback #2). Since 0.2.0 such a drop already reached the window under the pointer, but the dimming stayed over that window and made it look as if it would not take the file. Dropped on another program's window, the Peek ends, as when that program comes to the front; cancelled with Esc, or dropped on a fence or the desktop, the dimming comes back and the Peek goes on.
- When PecoFence closed because of a crash inside ExplorerPatcher, the notice at the next start says so and how to stop it (feedback #81). ExplorerPatcher registers itself as a shell extension, so its DLL loads into every program that shows the shell's folders, PecoFence included, and a crash in it ends PecoFence. Instead of 「PecoFence 上次意外关闭了。」, the notice now names ExplorerPatcher and says what helps: in ExplorerPatcher's Properties › File Explorer, untick “Register as shell extension”, then restart File Explorer.
- `pecofence-cli status` says for each monitor what the fences make of a live wallpaper (feedback #76): `liveWallpapers` lists `captured`, `notCapturable` (Wallpaper Engine's scene wallpapers and other players a capture cannot read; the fences show a neutral colour), `pending` (not captured yet) or `none`. `pecofence-cli snapshot restore <id> --dry-run` lists the fences the restore would add, remove, move or change otherwise (`updated`, with the fields that change, such as `rolledUp` or `items`) without restoring anything.
- Icon sizes between the fence menu's four (by @uvw): 「图标大小」 in Settings › 栅栏 is a slider from 24 to 128 px in steps of 4. Its ticks are the menu's 32, 48, 64 and 96, the thumb snaps to one it comes within 4 px of, the arrow keys move it by 4 px, and while it is dragged a bubble over the thumb shows the size. The fence follows the drag about 10 times a second; with 「调整大小时按整行整列对齐」 on it snaps to whole columns and rows once, on release, and a fence with 「向上展开」 that grows stops a gap short of the fence above instead of covering it. 「默认图标大小」 in Settings › 常规 is the same slider. The fence menu and Ctrl+wheel keep the four sizes: at a size between them no item is checked, and Ctrl+wheel goes on to the next one. Ctrl+wheel leaves a fence alone while 「锁定位置和大小」 is on; 「桌面」 arranged with 「像桌面一样排列」 has no lock, so Ctrl+wheel changes its icon size as on the Windows desktop. Its cells there follow the icon size, the spacing and the labels like a fence's. `pecofence-cli fence set <fence> iconSize 72` and `settings set iconSize 72` take the same range. A default size between the four makes older versions refuse every `pecofence-cli settings set` until it is set back to 32, 48, 64 or 96.
- Any icon spacing from 「紧凑」 to well past 「宽松」 (by @uvw): 「图标间距」 in Settings › 栅栏 is the same kind of slider, from 12 DIPs narrower to 32 DIPs wider than 「标准」 in steps of 4, with 「紧凑」, 「标准」 and 「宽松」 under their ticks at -12, 0 and 16. The cell height changes by three quarters of the width change, rounded to a multiple of 4 DIPs, and a narrower cell takes the height from the gaps around the icon so the label still fits. A fence without automatic height takes the height of its icons, as after a new icon size. Fences saved with a preset keep their exact cells. A value between the presets is saved as `spacingPx` next to `spacing`, the nearest preset, which older versions show. `pecofence-cli fence set <fence> spacingPx 8` sets any value, `spacing compact` still picks a preset, and `fence get` reports both.
- Icon labels can be hidden (by @uvw): 「图标名称」 in Settings › 栅栏 shows each icon's label on one, two or three lines, or hides it with 「不显示」; `pecofence-cli fence set <fence> labelLines 0` does the same from a terminal. Without labels each cell shrinks to a square around its icon, so more icons fit in a row and the fence gets shorter (one without automatic height too, as after a new icon size, and it grows again when the labels come back), and the first column still lines up with the title. An icon's name shows in its tooltip when the pointer rests on it, and also when the arrow keys, type-to-select or a Peek search move to it; F2 opens the rename box under the icon. In Settings the choice is greyed out for a fence in the list or details view, but not for 「桌面」 arranged with 「像桌面一样排列」, which always shows icons. Two lines by default; older versions draw a fence with hidden labels with broken cells.
- Infotips appear: when the pointer rests on an icon, its name, type, size and date show in a tip, as do the full title of a shortened tab and 「向上」 on a portal's up button. No tip ever appeared before: PecoFence loaded the old Windows tooltip control (comctl32 5), which refused the tip's description. PecoFence now asks for the current controls (Common Controls 6), as Explorer does, so the tips look like Explorer's and turn dark in dark mode, and the delete-fence question gets Windows 11 buttons. A tip hidden by a click, a key or the wheel comes back only once the pointer moves, and icon tips follow Explorer's "Show pop-up description for folder and desktop items" (Folder Options › View), as the desktop does.
- 「鼠标悬停时切换标签页」 is on by default: resting the pointer on another tab of a fence switches to it after Windows' hover time, as a click would. New configurations start with it on; a configuration that already has the setting keeps its choice, so turn it on in Settings › 常规 › 行为 (or `pecofence-cli settings set rollUp.switchTabOnHover true`) if you used PecoFence before.
- Settings › 整理规则 shows how to let an AI assistant tidy the desktop (feedback #87). AI assistants that can run commands, such as Claude Code or Codex, could already list the desktop items, create fences, move icons and add rules through `pecofence-cli`, but Settings never mentioned it. The new 「AI 助手」 card copies a ready prompt for the assistant (it asks it to read `pecofence-cli skill`, back up the configuration and propose a plan before carrying it out) and opens the CLI guide. The prompt names the CLI the way your edition runs it: `pecofence-cli` in the Store edition, the full path of `pecofence-cli.exe` for the setup and ZIP editions.
- A shortcut can show the Windows desktop for a while (feedback #84, and #42, #70): 「临时显示 Windows 桌面」 hides every fence and shows the Windows desktop icons, so you can move files around on the Windows desktop; the next press brings the fences back and hides the icons again. Record the shortcut in Settings › 常规 › 临时显示 Windows 桌面 the way you record the Peek shortcut; it has none until you choose one, so no keys change for anybody. The tray menu has the same entry, and `pecofence-cli windows-desktop start` / `end` does it from a script. Nothing of it is saved: 「隐藏 Windows 桌面图标」 stays as it is, and quitting or signing out meanwhile shows the icons, as always.
- 「图标名称颜色」 白色 and 黑色 also colour the fence titles, the tabs and the item count of a rolled fence (#141, suggested by @HaydenBL). They changed only the item names, so the titles still picked dark or light text from the wallpaper, and a fence could show white names under a dark title. Fences and tabs whose 「标题颜色」 is 「跟随主题」 now take the chosen colour; a fence or tab with a title colour of its own keeps it.
- Every fence can hide while it is empty (feedback #88, and #48): 「为空时自动隐藏」 in Settings › 栅栏, or `pecofence-cli fence set <fence> hideWhenEmpty true`, was only offered for 「桌面」. A fence with it on goes away with its last icon and comes back at its place when a rule, 「移动到栅栏」 or `pecofence-cli item move` puts an icon in it, or a new file appears in the folder a folder fence shows. A fence shown as a tab, or holding tabs, stays, as 「桌面」 does, and a folder fence stays while it shows a subfolder, and any other fence while it shows a folder opened in it. It is off for every fence until you turn it on.
- Custom colours (#140 by @xan2622, suggested by @roncli in #138). The colour swatches of 「图标着色」 (Settings › 常规) and of 「色调」 and 「标签页颜色」 (Settings › 栅栏) have a 「自定义颜色」 swatch after the first one: it opens the Windows colour dialog, where any colour can be picked or typed in as red, green and blue values, for example the Windows accent colour, which the dialog offers in its first custom colour slot. The swatch then shows the picked colour, and keeps showing it after another colour is chosen, until PecoFence closes.
- The bundled `SKILL.md` loads in GitHub Copilot CLI. Its description is quoted now: the colon in it made the frontmatter invalid YAML, and Copilot skipped the skill without a word.
- A double-click on a folder, or on a shortcut to a folder, can open that folder inside the fence, as Explorer opens it in its own window (#132, by @xan2622). It is an option of each fence, off by default, so nothing changes until it is turned on: Settings › 栅栏 › 「双击文件夹或文件夹快捷方式时在此栅栏内打开」, or `pecofence-cli fence set <fence> openFoldersInside true`. The fence then shows the folder's files under the folder's name (a drive's root as "Local Disk (C:)"), with an up arrow (also Backspace and the fence menu) that goes back through the subfolders and, from the folder opened, to the fence's own icons. Shortcuts with environment variables in their target (`%USERPROFILE%\Documents`) work too. Several items opened at once and a Peek search match still open folders in File Explorer. While a fence shows a folder, 「移出栅栏（放回“桌面”）」, a drag onto the bare desktop, 「移动到栅栏」 and `item move --to` only change which fence an icon is in and never move a desktop file into that folder; files dropped on the fence itself go into the folder it shows. `fence get` reports that folder as `openedFolder`, and `item list` and `watch` keep to the fence's own icons. Folder fences work as before (「双击子文件夹时在此栅栏内打开」).
- **Keep Windows desktop icons hidden when PecoFence closes**, under **Hide Windows desktop icons** in Settings › General. At sign-in Windows shows its desktop icons for a moment, until PecoFence starts and hides them. With this on, PecoFence leaves them hidden when it exits or you sign out, so they don't flash at the next sign-in. While PecoFence isn't running, the desktop then shows no icons. A crash still shows them, and so does uninstalling the installer edition. Uninstalling the Microsoft Store edition, deleting a portable copy or going back to an older version of PecoFence leaves them hidden: turn this off and exit PecoFence first, or afterwards right-click the desktop and choose View › Show desktop icons. `pecofence-cli settings set keepIconsHidden true` does the same from a terminal.
- Folders can stay above files in a fence (#143 by @uvw, suggested by @roncli in #139): 「文件夹优先」 in the fence menu's 「排序方式」 keeps them on top in every order, also with 「倒序」, and the Recycle Bin and the other system items stay above them. In a fence sorted 「手动」 it sorts 「按名称」, and it and 「按时间分组」 turn each other off. `pecofence-cli fence set <fence> foldersFirst true` does the same from a terminal. Off by default.
- Fences can expand upward (suggested by @Playmyone in #125). With 栅栏选项 › 向上展开 (`pecofence-cli fence set <FENCE> expandUpward true`) a rolled-up fence opens upward from its title row when it fits above it, so one resting on the taskbar no longer opens behind it; where it does not fit above but fits below, it opens downward like any fence, and where it fits on neither side it opens toward the larger room, as far as that goes. The title row always stays where you put it: the fence rolls back up to it, after a restart too, and switching the option on or off never moves the fence. This holds for a click, a hover peek, `fence unroll` and an auto-height fence opening to show every icon. With 展开时把下面的栅栏推开 on, the fences resting above a fence that opens upward slide up out of its way and come back when it rolls up, the way the ones below a fence slide down; they never leave the screen, and the room they can make counts when the fence picks its side. A fence with the option is never pushed itself. `fence resize --h` and `fence fit` keep the edge it opened from (`bottomAnchored` in `fence get`).
- After 「显示桌面」 (Win+D or the far corner of the taskbar) with 「保持栅栏可见」, Settings and the 「属性」 window of an icon open on top of the fences (#133). The fences float above every window until another window comes to the front, and every window of PecoFence counted as one of the fences, also Settings and the Properties window, which Windows opens inside PecoFence; so both stayed under the fences. Only the fences, their menus and PecoFence's small popups keep the fences floating now.
- On Windows 10, fences no longer stay above the other windows while a program running as administrator has the lowest window above the desktop (feedback #91). Windows does not let PecoFence put a fence below such a window, and the way around it from 0.1.4 only works where the desktop is the bottom window (Windows 11 24H2 and later), so after Win+D, Peek or a new fence the fences stayed above every app, a folder just opened from a fence included. The fences now go directly above that program's window, under all other apps.
- A report sent from 「反馈」 says how many fences sit above other windows (feedback #92), next to how many are topmost or behind the desktop, so a report about fences covering other windows shows it directly.
- Fluent fences have clean round corners. Windows rounded their windows by 4 px while the 1 px edge curved by 8, so a sliver of the plate showed outside the edge at every corner, and on Windows 10 the corners were square. Fluent fences now round their own corners by 8 px (the Windows 11 window radius), as Liquid Glass does with 16, also on Windows 10; the shadow follows the same curve.
- Custom themes (suggested by @HaydenBL in #84). A JSON file in the `themes` folder next to `config.json` starts from Fluent or Liquid Glass and changes some of its values: the blur and tint of the wallpaper behind the fences (a frosted Liquid Glass, for example), the Liquid Glass lens (refraction, rim light), the corner radius, the shadow, the fonts of item names and of titles, the accent and the colours (a colour of their own for fence titles and tabs, too), and the halo around text on the wallpaper or a soft shadow under it, in both colour modes or in one. Sizes and layout stay as they are, so a theme never moves or resizes a fence. Settings › 常规 › 自定义主题 lists the theme files and opens the folder, which starts with three example themes to pick or copy (a frosted Liquid Glass, a warm Fluent and a Fluent with larger corners); `pecofence-cli settings set customTheme <name> --string` does the same from a terminal. The fences change as soon as the file is saved. A file that cannot be read or has a mistake keeps the built-in style, and Settings says what is wrong. [THEMES.md](docs/THEMES.md) describes the format.
- In the Microsoft Store edition, the fences take a new desktop picture at once (feedback #95). After a picture was set in Windows Settings › Personalization › Background or with Set as desktop background in a picture's right-click menu, or when a slideshow moved on, the fences kept the old picture behind their glass for up to about 5 seconds (Liquid Glass shows it most), and when the picture changed while a fence menu or a dialog of PecoFence was open, until up to 5 seconds after it closed. Windows does not tell a Store app when another program changes these settings, so PecoFence only noticed the new picture when it looked again every 5 seconds. It now also watches the folder where Windows keeps its copy of the desktop picture, whose changes do reach a Store app.
- A click on the desktop or in another fence takes the selection off the icons of the other fences (feedback #66 and #137; #135 by @dxiiren). The icon you clicked last stayed selected in grey, so after a few clicks every fence showed one, until you clicked an empty spot in that very fence. When you switch to another program, open a file, open its 「属性」 or a QuickLook preview, or press the Peek hotkey, the selection stays and turns grey, as in Explorer, until the next click on the desktop or in another fence.
- An icon dragged out of a fence onto the empty desktop stays in 「桌面」 (feedback #49), as with 「移出栅栏（放回“桌面”）」 in its menu. The sorting rules then ran on it at once, whether 「新项目出现在桌面时自动归类」 was on or off, so a shortcut went straight back to 「程序」 and could not be taken out of its fence by dragging. Icons new on the desktop are still sorted by the rules.
- A file or folder dragged from the Recycle Bin window into a fence gets its name back (feedback #50), as when Explorer restores it. It kept the name the Recycle Bin gives it on disk, such as `$R7AB12C.docx`.
- A folder or a file without an extension opens itself from a fence, also when a program or a shortcut of the same name lies beside it (feedback #51). A folder `Foo` next to `Foo.lnk` opened the shortcut's program, and a file `README` next to `README.bat` ran the batch file, because Windows tried the name with `.com`, `.exe`, `.bat`, `.lnk` and so on first. PecoFence now hands Windows the item itself, as Explorer does.
- 「展开时把下面的栅栏推开」 also pushes fences that are 「锁定位置和大小」 (feedback #52), and lifts them like the others above a fence that expands upward. The expanded fence covered a locked fence below it, and after a restart with the upper fence saved expanded, the locked fence was even moved out of the way for good. A push only moves the window while the fence above is expanded, so a locked fence keeps its saved place and size.
- Delete, Ctrl+X, Ctrl+C and Explorer's commands in the icon menu work on a selection that holds both your own desktop icons and icons of the Public Desktop, where installers put shortcuts for all users (feedback #21). Windows found no single folder holding both, so Delete did nothing and the menu showed only PecoFence's own commands. Such a selection now goes to Windows as items of the desktop, as on Explorer's desktop; a shortcut only administrators may delete asks for that permission, as in Explorer.
- Deleting a file or folder in a fence, or dragging it onto the Recycle Bin, no longer makes PecoFence stop responding when the Recycle Bin holds many items (feedback #47, and in #120). With 「隐藏 Windows 桌面图标」 on, PecoFence asks Windows after every change whether the Recycle Bin is empty, to show its full or empty icon, and Windows counts every item to answer. With 30,000 items in the bin each answer took about 5 seconds, during which the fences did not react, and deleting a folder cost three answers in a row. PecoFence now asks in the background, and the icon changes when the answer comes.
- 「清空回收站」 in the menu of the Recycle Bin in a fence works when the files in it were deleted in another program (feedback #48). In the Store edition Windows does not tell PecoFence about files other programs move to the Recycle Bin, so once the bin had been emptied, the entry Windows adds to the menu stayed grey, and the bin kept its empty icon, although it was full again. The menu now has PecoFence's own 「清空回收站」, which asks the bin when the menu opens; opening the menu also brings the bin's icon up to date.
- A report sent from 「反馈」 carries more of the log, and the log says more of what happened (feedback #95, #96). The report sends up to 50 KB of log instead of 24 KB (a little less with a very long message, so that the report always fits what the service takes): the first 8 KB (the start, with the settings and the fences the run began with), the end, and from the stretch in between the warnings, errors and key events (display changes, the desktop coming to the front, fences hidden by a double-click, show desktop, settings changed). When the current run has only just started, the run before it goes along too, since you may have restarted PecoFence after the trouble. The log now records where each fence is placed after a display change and why, the window size Windows suggests when a fence moves onto a monitor of another scale, when a fence's saved place or size changed without you (auto height, fitting, a monitor change) and why, what hid or showed the fences, which window the desktop handed the front to, which window covered the fences, whether the wallpaper change signals arrived, locking and unlocking and Remote Desktop connections, where new desktop items were sent (by a rule, to 「桌面」 or nowhere), which settings changed (their names, not their values) and from where, which file the settings were read from at the start, why PecoFence quit, sleep and wake, and the command that was running at a crash. Short delays that filled earlier logs (commands of 8 to 50 ms, small animation hitches) are counted in one line an hour instead. The 「反馈」 system facts add each display's position, whether this copy came from the installer, a ZIP or the Store, the drives of the program and its settings, whether it runs in a Remote Desktop session, the live wallpaper and the last display change. As before, the log keeps no file, folder or fence names.
- When PecoFence stops responding for 5 seconds, its log says which command was running and where it was stuck, and how long it took to respond again. When a run did not end normally (it was ended while not responding, or from Task Manager), the 「反馈」 form also sends that run's log, as it already did after a crash.
- When Windows will not let the Store edition read its saved settings because the files are not encrypted (Windows error 409, feedback #56), PecoFence says so and what helps. The Store edition installed on a drive other than C: keeps its data on that drive, and Windows reads files there only when they are encrypted; on some PCs they are not, so every start found neither `config.json` nor its backups and began with the default settings, and the snapshots were gone too. A tray notice now suggests moving PecoFence to C: (Windows Settings › Apps › Installed apps) or using the portable edition, and so does 「恢复」 of a daily backup. The log names each saved file that could not be used and why, and a 「反馈」 report says the same and why it carries no log.
- A file shows its own thumbnail or icon in a fence whenever Explorer shows one (feedback #48). Besides programs and shortcuts, only a fixed list of picture and video types got a picture of each file; every other file got the icon of its type, asked once for all files of that type. And with the Windows desktop icons showing, dragging This PC or the Recycle Bin from the desktop onto a fence put the shortcut Windows makes (「此电脑 - 快捷方式」) into whichever fence the rules picked; it now goes into the fence you dropped it on.
- The Peek shortcut can be any combination you like (feedback #26). Two of the three choices, Win+Space and Win+Shift+Space, never worked on Windows 10 or 11, which keep them for the input switcher even with a single keyboard layout, and Settings kept showing them while Peek had quietly moved to another one. In Settings › 常规 › 速览栅栏, click the shortcut box and press a combination with Ctrl, Alt or Win; PecoFence takes it at once, or says that Windows or another app already uses it. 「包含 Win 键」 adds Win to the next combination, since Windows catches many Win shortcuts before Settings sees them. Combinations that would take common Windows functions away (Ctrl+Space, Alt+Space, Alt+Tab, Ctrl+C, Win plus one key, and the like) are refused. Ctrl+Alt+Space stays the default, Win+Alt+Space and Ctrl+Shift+Space replace the two Win+Space choices, and Settings now shows the shortcut that really works, with a note when the chosen one is taken. pecofence-cli sets it with `settings set peek.customHotkey Ctrl+Shift+F`. A configuration from 0.2.0 still opens, and 0.2.0 still opens one saved now (it uses Ctrl+Alt+Space there).
- With two Windows accounts signed in at the same time, `pecofence-cli` and a second start of PecoFence work in both (feedback #13). The named pipe the CLI talks through had one name for the whole computer, so in the account whose PecoFence started second the CLI was off (`pipe name unavailable; CLI disabled` in the log): pecofence-cli there failed with "Access is denied", or, run as administrator, reached the other account's PecoFence, and starting PecoFence again did not open its Settings. The pipe name now contains the account's SID (`\\.\pipe\PecoFence.<SID>`), so each account reaches its own PecoFence, also from another session of the same account such as an ssh login.
- PecoFence keeps less memory between uses. Half a minute after the fences last drew something, it hands the memory the last use touched back to Windows, every time instead of only once after startup; what it needs again comes back on its own, with no visible delay (the first animation after a pause measured the same as before). On a 4K monitor the memory Task Manager shows for PecoFence at rest stays at about 2 to 5 MB, where it used to grow to about 28 MB after some hours of use. Settings, Peek and a name being edited keep their memory while they are open.
- A report of PecoFence using far more memory than usual (a user saw 366 MB in Task Manager) can now say where it went. Task Manager's number only counts what sits in RAM right now, so the report's memory line also gives the memory PecoFence has reserved and its graphics memory (dedicated and shared), and the diagnostic log gets a memory line once an hour and whenever these grew by 64 MB, so the log shows when the growth happened and next to what.
- A crash inside another program's code, such as a graphics driver, can now be traced from the report it leaves (feedback #22). PecoFence 0.1.5 closed for a Store user while the AMD graphics driver redrew a fence, and the report showed only where in the driver it happened. The crash line in the log now also says whether the failing instruction read, wrote or ran code and at which address, and gives the file version of the module it was in and of pecofence.exe. A report sent from 「反馈」 also names the graphics adapter the fences are drawn on and its driver version (`gpu:`), without serial numbers or other identifying data.
- The box for a new name opens on top of the fence after Win+D (「显示桌面」) and during Peek (#99). The fences float above every other window then, and the rename box (F2, 「重命名」 in an icon's menu, or a fence title) opened behind its fence: through Fluent it showed only faintly under the old name, through Liquid Glass hardly at all, so renaming looked broken.
- Every tab switch and every fence fading in or out kept a little memory (about 0.3 KB) until PecoFence quit, roughly 1 to 10 MB over a week of use. It is now released when the animation ends.
- Changing a fence's icon size, spacing, label lines or view reuses the graphics memory the fence already has. Until now each change kept about one fence picture's worth of video memory until PecoFence restarted: on a 4K monitor twelve icon size changes added about 100 MB in Fluent and about 220 MB in Liquid Glass, and the total grew with every change. It now stays where the first change left it.
- When PecoFence's graphics memory still grows well past where it started (by more than 64 MB, for example after many resizes to new sizes or with Liquid Glass), it sets up its graphics anew half a minute after the last change, at most every five minutes. That takes about 0.07 s with Fluent and 0.3 s with Liquid Glass and changes nothing on screen, and the memory goes back to where it started. On integrated graphics this memory comes out of the computer's RAM.
- Photo thumbnails and icons no longer pile up in memory. PecoFence keeps the icons its fences show, in every tab and at the current icon size, and lets the others go a few seconds after a change: another icon size or screen scaling, a folder a portal has left, a fence closed or deleted, files deleted from the desktop. Ten folder portals of 300 photos each, opened and closed one after the other, used to leave about 190 MB in use for as long as the photos existed; now PecoFence is back at about 12 MB after each one. Going back into a folder reads its icons again, so a big folder of photos may show grey tiles for a moment.
- Liquid Glass keeps the wallpaper for its refraction at half the monitor's resolution, a quarter of the graphics memory it took: on a 4K monitor about 8 MB per wallpaper instead of 33 MB (two wallpapers when virtual desktops differ). The glass scales it back up with linear filtering, which looks the same through the glass; Center and Tile wallpapers keep their native scale, as the picture is still decoded at full size first.
- Icons dragged out of a fence onto empty desktop go back into 「桌面」 again, as intended (feedback #31). Explorer's desktop took such a drop itself: This PC and the Recycle Bin left a 「此电脑 - 快捷方式」 or 「回收站 - 快捷方式」 behind, which the rules then filed into 「程序」, so This PC showed up there once more after every drag; a file brought up Explorer's "The source and destination file names are the same" dialog, the fences did not respond until it was closed, and the icon stayed where it was. PecoFence now ends such a drag itself when it is released on empty desktop, with the Windows desktop icons hidden or shown. Holding Alt still makes a shortcut there, a file dropped on a folder icon Windows shows on the desktop still moves into that folder, and This PC dropped on a folder in Explorer still makes a shortcut in it.
- The fences show the wallpaper through Fluent and Liquid Glass again when the picture file it was set from no longer exists (feedback #35). Some wallpaper apps set the wallpaper from a temporary file and delete it afterwards, and a picture can be moved or deleted after you chose it. Windows keeps showing its own copy, but PecoFence could only read the original file, so the fences got a plain backdrop and the styles looked broken (`wallpaper unavailable at startup` and `backdrop refresh deferred until wallpaper is readable` in the log). PecoFence now builds the backdrop from the copy Windows keeps, and still follows every new wallpaper.
- With 「调整大小时按整行整列对齐」 on, the icons stay put while a fence is resized (#118). A height that is not a whole number of rows, as when an edge lines up with another fence, used to share the extra height out between the rows, so the icons jumped up and down each time the dragged edge passed another fence's edge. The rows now keep their spacing: the extra height stays empty under the last whole row, and a row that would only show in part is cut off there, so the fence still shows whole icons only.

## 0.1.2

- Liquid Glass reworked after kube.io's refraction model: the face of a fence stays perfectly clear and all the bending sits in the rim, where a convex squircle bezel refracts the wallpaper with Snell's law (index 1.5). The very edge mirrors the backdrop like thick glass, and the magnification eases out over 40 DIP so no inner frame shows between the rim and the clear face. A thin specular ring is filled with the refracted wallpaper's colour, strongly saturated. The old material's whole-panel warp, blur and colour fringes are gone, and Liquid Glass corners are now 16 DIP. Moving a fence draws faster (one displacement pass instead of three), and GPU memory peaks lower while arranging fences (about 160 instead of 450 MB with 7 fences on a 4K monitor).
- Fences line up when resized, whatever their icon size, spacing or view: a dragged edge, top and bottom included, snaps to other fences' edges (level, or a gap apart) and to the work area's edges, with alignment guides, also with 「调整大小时保持为整数个图标」 on. Away from them that option still sizes to whole columns and rows; at a height of no whole rows the rows share the space left over like the columns share the width, so a fence still shows whole icons only. Dragged edges, expanding a rolled fence and the automatic size changes stop exactly a gap short of the next fence instead of a whole row short. Switching the option on, a late DPI change at logon, tab changes and restoring a layout no longer re-round sizes; changing a fence's icon size, spacing, view or label lines still does (#1).
- Tab names no longer vanish on a narrow fence: squeezed tab pills give up their padding (down to 8 DIP) before a caption is shortened with an ellipsis.
- Alignment guides while dragging (「显示对齐参考线」, `snapping.guideLines`, on for new configurations): thin white lines along the edges a moved or resized fence lines up with, and along the screen's centre line when it snapped there.
- Dragged fences also snap to the screen's centre lines (centred horizontally / vertically on the work area). Holding Alt while dragging or resizing moves freely, without snapping.
- When a dragged fence's title is over another fence's title, that fence gets the white outline: releasing there adds the dragged fence to it as a tab. The outline used to disappear in that spot, which looked like a glitch.
- The drop outline no longer stays on screen after a Liquid Glass drag is cancelled with Esc or a right-click, and no longer flashes on top of the dragged fence every two seconds (the desktop-layer check took it for a foreign window).
- The 「在此新建栅栏」 menu that appears after drawing a rectangle on the empty desktop closes again when you click elsewhere or press Esc. It used to stay open until its item was chosen, and rectangles drawn meanwhile queued up more of them.
- The settings window follows Windows 11 Settings: neutral colours, plain 20 DIP icons, 14 / 12 px text and On / Off captions beside every switch; the slogans, the banner picture and the tinted sidebar are gone. Fluent and Liquid Glass are picked from two preview tiles that show the icon size, tint and Chameleon settings live. Icon tint and fence tint are colour swatches; alignment guides and the Peek hotkey sit under the switch they depend on and turn grey while it is off. Rules are one compact row each, the quick-add templates are chips inside their card, and the new-rule form opens on demand. The fence picker heads the 「栅栏」 page, and restoring the desktop icons moved to 「故障排除」 on the About page. Chinese, Japanese and Korean text in the window uses the font of the interface language, and 「显示语言」 is listed under 「外观」 again.
- Chinese file names and titles in fences are drawn with Microsoft YaHei UI. They used to come out in the Japanese UI font, with Japanese forms of shared characters (今, 令, 骨, 直) next to YaHei for simplified-only ones. Like Explorer, fence text follows the Windows display language: Traditional Chinese uses Microsoft JhengHei UI, Japanese Yu Gothic UI, Korean Malgun Gothic, every other language YaHei.
- Select several fences by drawing a rectangle on the empty desktop: every fence it touches is selected as you draw (Ctrl or Shift adds to the selection) and gets a white outline, like the other drag feedback. Drag any selected fence by its title and the whole group moves along, keeping its layout; the group's outline snaps to the other fences and the screen edges, Esc or a right-click puts it back. A click on the desktop or on any fence ends the selection. While the desktop icons are hidden PecoFence draws the selection rectangle itself, in white too (Explorer shows none then). A rectangle that touches no fence still offers 「在此新建栅栏」, and a drag that activates the desktop from another window now counts too.
- 「鼠标悬停时才显示标题栏」 no longer leaves an empty band at the top of every fence: at rest the title row folds away and the glass starts at the icons; when the pointer arrives, the glass grows back up and the title fades in, with the icons staying where they are. The shadow and the rounded corners follow the glass.

- 「全透明」 opacity (fence options, `opacity transparent`): no glass, tint, border or shadow at rest, only icons and titles, whose text picks dark or light ink from the wallpaper and gets a halo. ## 0.1.1

- Switching virtual desktops no longer blanks the fences: they slide out and in with the desktop, content and glass together, instead of disappearing for the whole animation and popping back afterwards. The other desktops' wallpapers are prepared in the background, so a fence already shows the new desktop's picture as it slides in (about 33 MB more per extra 4K wallpaper). During taskbar-thumbnail Aero Peek fences now fade like other windows.
- Less memory with Liquid Glass: on a 4K monitor with 7 fences the idle private working set drops from about 97 to 40 MB and GPU memory from about 200 to 80 MB. - Fences no longer grow into each other: expanding a rolled fence, changing the icon size, auto height and the cell snap stop a snapping gap short of the next fence (the rest of the items scroll), and a dragged edge stops at a neighbouring fence. A fence dropped onto another one moves the shortest way to a free spot (an outline shows where while you drag), and overlaps a layout already has are pulled apart at startup (larger fences stay, smaller ones move; with no free spot a fence stays put) (#2).
- Changing a fixed-height fence's icon size fits its height to the content, so shrinking the icons no longer leaves rows of empty space (#2).
- Snapping settings now match Stardock Fences: 「移动栅栏时吸附对齐」 (keep fences lined up when moving), 「栅栏间距」 (space between fences, 0–32 px, back on the settings page) and 「调整大小时保持为整数个图标」 (`snapping.sizeToCells`, whole icon columns and rows, which was stored but did nothing). With it off (the default) a fence can be any size: the icon grid spreads its columns over the width, a fence keeps its width when the icon size changes (it used to grow or shift left) and a dragged side edge snaps to neighbouring fences' edges (#1, #2).
- Smoother icon edges: icons from the shell came with straight alpha but were drawn as premultiplied, which made anti-aliased outlines look jagged, most visibly at large sizes on dark wallpapers (#2).
- 「在桌面显示文件夹」 (Show a folder on the desktop) in the tray and fence menus shows Documents, Downloads, Pictures or any chosen folder as a live fence; the UI no longer says "portal".

Found by letting an agent organise a real desktop with the CLI:

- pecofence-cli: `item move --dry-run` (method `items.planMove`) lists per item whether only the icon changes fence (`membership`), a real file moves (`fileMove`, with `destination`), nothing happens, or it is skipped (`exists`, `notAFile`). The real move now skips files whose name already exists at the destination (`skipped` + warning) instead of opening Explorer's replace dialog on the user's screen, and says `fileMove: true` when files are still on their way.
- pecofence-cli: `fence get` / `fence list` report `fit` (columns, rows, the height that shows every item, `overflow`) for the fence each window shows; `fence fit <FENCE>` applies that height.
- pecofence-cli: when the app changes a rect on its own (auto height after `fence move/resize/fit` or `fence create --rect`, whole columns and rows after `fence set iconSize/spacing/layout/labelLines`), the reply carries `adjusted {requested, applied, reason}` instead of a silently different size.
- pecofence-cli: `fence create --below/--above/--right-of/--left-of <FENCE> [--size w,h]` places a fence next to another one with aligned edges and the snapping gap, refuses rects that leave the work area and warns about overlaps.
- pecofence-cli: global `--fields id,title,rect.w` keeps only those keys (no jq needed) and `--ascii` writes non-ASCII as `\uXXXX`, for readers that decode stdout with the ANSI code page (Python on a Chinese or Japanese system, Windows PowerShell 5).
- pecofence-cli: `item list` reports `shortcutArguments`, so the same program started with other arguments no longer looks like a duplicate.
- pecofence-cli: a folder portal that has been navigated into a subfolder reports it as `portal.current`; `item list` shows that folder and `item move` to the portal puts files there.
- pecofence-cli: a hosted tab's `rect` is now its host window's (it was the tab's stale own geometry, which made fences look overlapped); snapshots report `fenceCount` for the current monitors (it used to sum every monitor layout, e.g. 21 for 7 fences).
